## 2. `P10.F3` — verified, not accepted

Four things carry the slice, and each could be wrong in a way that puts the mark back where the
operator rejected it. I re-measured all four by my own methods.

### 2.1 The load-bearing fact: Hangul *does* carry a descender — **reproduced**

`P10.F3` found the plan's premise («Hangul carries essentially no descender») **false for the rendered
type**, and built the whole law on that. My method: canvas `TextMetrics` with **each element's own
computed `font` shorthand**, reading `actualBoundingBoxDescent` (ink below the alphabetic baseline).

| element | size / weight | ink below the alphabetic baseline |
|---|---|---|
| `.link` `보유 종목` | 13.5px / **600** | **1.158** px |
| `.link` `AI 질문` | 13.5px / 400 | **0.916** px |
| `.utility` `로그인` | 13.5px / 400 | **0.781** px |
| footer `.source` | 12px / 400 | **1.016** px |

`P10.F3` reported 1.05 (400) / 1.16 (600) at 13.5px and 1.02 at 12px. **I reproduce it**, and the
range is in fact wider than it stated — **0.78–1.16px**, because different syllable sets have
different block bottoms (this is also why *which label you point the law at* matters, §2.3). The
premise is false; the correction was right to make; the adopted "Hangul block bottom" reading is the
one the eye reads.

### 2.2 Which face is actually rendering — **Noto Sans KR, and the docs already say so**

The plan flagged a possible durable-truth error (F3's prose names Noto Sans KR; the phase's history
carries the operator's gate answer *"Pretendard 600"*). Measured three ways, in both runtimes:

- **computed `font-family`** on the nav label, the utility slot and `.source`:
  `notoSansKr, "notoSansKr Fallback", system-ui, …` — Pretendard appears **nowhere**.
- **`document.fonts`**: `notoSansKr|100 900|loaded`, `plexMono|400/600|loaded`, plus Next's own
  unloaded Geist entries. **No Pretendard face of any kind**, on all 8 reader routes and all 6 `/ops`
  routes, dev and production.
- **`CSS.getPlatformFontsForNode`** (the face Chrome actually resolved): reader nav label →
  one `isCustomFont: true` face, `OTS-derived-font_Regular`, **glyphCount 5** for `AI 질문`;
  `/ops` bar mark → one custom face, `OTS-derived-font_SemiBold`, **glyphCount 9** for
  「주주의관제탑 운영」 — nine of nine glyphs in one face, weight **600**, `letter-spacing: normal`,
  box **91.69 × 18.59**.

**There is no naming error to fix.** `architecture.md`, `frontend.md`, `qa.md` and `decisions.md` all
say Noto Sans KR and record Pretendard as *retired*; `decisions.md` already states in as many words
that the operator's *"drop mono, use Pretendard 600"* named a **weight**, and that the family
underneath it was replaced in the same slice, so the mark lands as **Noto Sans KR 600**. So round 4
owes **three** doc-impact entries, not four. Reported rather than silently dropped, because the plan
asked for a finding either way.

floor**; and (b) the document itself (rects, computed transforms, canvas metrics). At 390 the raster
is **24×** (dsf 3 × scale 8) and the arithmetic follows.

## 9. Deviations from `plan.md`

1. **The production build was verified on `:3011` / `:3012`, not on `:3010`.** The manifest's
   production path is `npm run build && npm run start` on the **same origin as dev**, which requires
   stopping the dev server first — and this environment's command policy **refused `make stack-down`**
   (twice, as a blocked action). Rather than work around a denial aimed at the operator's running
   stack, I ran the same production build on a spare port and left the operator's dev server up. What
   this could have hidden is origin-sensitive behaviour (CORS, CSRF, dev-origin allow-lists); what it
   demonstrably did not hide is anything measured here — **every one of the 12 compared fields plus
   both `<img>` descriptors is identical between dev and production on all 8 routes**, the API is
   reached normally from the production origin (board data renders, the live agent answers), and the
   footer's fractional layout tops match dev **to 1/64 px**, which they could not do if the page were
   rendering different content. Stated rather than glossed.
2. **`/ops` needed a second API and a rebuild.** With 8010 owned by the operator's stack and carrying
   no ops credentials, I started a throwaway API on **8011** with the credentials as environment
   variables. Next bakes `next.config.ts`'s rewrite destination into the build, so reaching it needed
   one `npm run build` with `MIJUAL_API_ORIGIN` set; **I rebuilt with the default immediately
   afterwards**, and `frontend/next-env.d.ts` (which `next build` rewrites) was restored to `HEAD`, so
   the working tree carries **no source modification** (§12).
3. **`qa.md` v0012 corrects two falsified lines the plan did not name.** The plan named
   「세로 기하는 움직이지 않았다」; the same supersession also falsifies the P10 rebrand block's
   `transform: translateY(-7px)` assertion and the round-2 크롬 마크 line's band-centre numbers. Both
   would now **fail on a correct build** — the precise defect this phase has shipped four times.
   Leaving them would have been the same error one round later, so I corrected them and recorded it
   here rather than doing it silently. I also added the client-rect/line-break caution (§1.2), which
   is not in any doc-impact note but cost round 3 and round 4 the same hour.

**Not a deviation, but worth stating:** §2.2 turned up **no** font-face naming error, so round 4 owes
**three** doc versions, not the four the plan allowed for.

## 11. What round 4 adds to the phase's own lesson

Four defects in this phase were **checks that could not fail**. The fifth — the one that reached the
operator — was different in kind: **R17's alignment check verified the mark against the wrong
reference.** It *could* fail. It passed, because it was measuring the row instead of the type.

So the rule this phase leaves behind now has two halves, and both are in `decisions.md` D-30:

> A guard is only a guard if some input makes it report failure —
> **and only the right guard if it is pointed at what the operator is actually looking at.**

Round 4 caught two more instances of the second half in its *own* work, which is the point of writing
it down: the mono `getClientRects()` count (9 false splits on a correct build) and the `innerText`
reading of a CSS margin (a phantom missing space). Both are now in `qa.md` v0012.
