### 2.1 The footer reservation is **108px**, and the record's 84px would have shipped the bug "fixed"

**From the product files:** `Footer.tsx:56` renders `className={`content ${styles.inner}`}` — one
element carrying **both** classes — and `app/shell.css` gives `.content` a `padding-inline: 24px`
**shorthand**, which sets the end padding too. So `padding-inline-end` on `.inner` **replaces** that
24px, it does not add to it. The launcher is `right: var(--space-6)` at 68px wide, so it occupies
`24 + 68 = 92px` from the viewport's right edge, and clearance is **`P − 92`**. `84 − 92 = −8`: eight
pixels of a 65.9px-wide button still under the launcher, which is the whole button as far as a
pointer is concerned. **108 = 68 + 24 + 16** is the only value that delivers the 16px of air the
record's own code block asked for.

then a real `click()`, then the panel closed again — production; dev identical except where noted):

## 6. Fresh eyes, as a first-time user — *not* judged against the design record

Observations for the operator to dispose of, never silent fixes. **None of these blocks the pass, and
none is a P10 regression** — where a cause is known it is named.

1. **The launcher's signed "open" state is never visible and never operable.** The widget is

2. **Esc does not close the AI 질문 widget** on desktop. The header × does, and Tab reaches it.
   Pre-existing (R14/P8); the Esc rule the checklist carries is for the ≤480 sheet and the citation
   popovers.
3. **At exactly 1256px the 의견 보내기 button and the launcher are flush at 0px** — the media query
   ends at 1255, so the reservation drops out one pixel before the geometry stops needing it. Still
