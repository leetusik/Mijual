## 1. 워드마크 재파생 (§①)

`frontend/public/assets/`에서 §①의 4줄 명령을 실행해 `juju2-wordmark-white.png`를 **같은
파일명으로** 덮어쓴다. `530 + 717 = 1247`, `575 = 530 + 45`.

**지워서는 안 되는 두 가지**(R17 함정 3·4): `-channel RGB … +channel` 가드와
`-define png:color-type=6`. 지우면 알파가 평탄화되어 흰 사각형이 된다.

재파생 후 §①의 검증 표를 전부 다시 잰다 — 단, **한 행은 예외다**:

> **「불투명 근백색 = 0」 행은 쓰지 말 것.** 흰 파생물 전체에 대해서는 그 값이 언제나 불투명
> 픽셀 수(69,630)이고, 무엇이 잘못돼도 걸러내지 못한다. `VERIFICATION.md` §2가 그 자리에 쓸
> 두 가지를 준다: **갇힌 카운터 두 섬**(`50×46 at (402,226)` → 비투명 481,
> `69×15 at (969,335)` → 15, **둘 다 수정 전과 같아야 한다**)과 **알파 splice 해시 비교**.

나머지는 그대로 확인: `1247x371 srgba` · 비투명 **78,212** · 완전 불투명 **69,630** · 서로 다른
알파값 **154** · 의\|관 간격 `x=519..543` · 스파클 `222×165 at x=1025` · 글자띠
`1087×176 at y=195`.

## 2. 워드마크를 읽는 코드 (§① 코드 변경)

- `components/chrome/copy.ts` — `WORDMARK_NATURAL`을 **1247**로. 주석에 한 문장: 1292는 4분의 1
  각공백이 들어간 수정 전 값이고 파생 명령이 그 45열을 잘라낸다.
- `components/chrome/Wordmark.tsx` — **`INK_OFFSET_PX`와 `translateY` 값은 절대 건드리지 않는다.**
  세로 기하가 하나도 변하지 않았다. 고칠 것은 **문서 주석의 수치뿐**: 「1292×371」 두 곳 → 1247,
  글자띠 `1132×176` → **1087×176**, 종횡비 3.4825 → **3.3603**. `76.28%` / `0.2628 × H` /
  `-7px` / `-6px` / `30 empty rows` / 「222×165, flush to the box's top and right」는 **무변**이다.
  주석이 렌더 폭을 말하는 곳이 있으면 nav **94.0 → 90.7px**, footer **83.6 → 80.6px**.

`app/layout.tsx`와 `Launcher.module.css`는 워드마크를 참조하지 않는다 → 이 항목에서는 무변.

## 3. 파비콘 타일 3개 (§③)

`frontend/`에서 §③의 세 명령을 실행한다. **함정 셋 다 조용하므로 명령을 그대로 쓴다**:
`-alpha off`가 없을 것, `png:color-type=6`일 것(2가 아니라), **재색칠이 리사이즈보다 먼저**일 것.

검증: 세 파일 모두 `srgba` + `opaque=false`, 잉크 트림 `24x18+4+7` / `134x100+23+40`, 잉크 RGB
`43,142,108`. (`-trim` 뒤에 `+repage`를 붙이면 오프셋이 0으로 리셋되니, 오프셋을 보려면 붙이지
말 것 — §③의 명령은 이미 그렇게 쓰여 있다.)

**`Launcher.module.css`의 `mask-size: 84% auto`는 유지한다.** 파비콘만 75%로 간다. 이 갈림은
R18이 의도한 것이고 `phase.md` `## Decisions`에 적혀 있다 — "일관성"을 이유로 런처를 따라
바꾸지 말 것.

`app/layout.tsx` — **`icons` 키는 계속 넣지 않는다** (Next `app/` 파일 컨벤션이 유효하다). 주석의
**틀리게 된 사실 두 개만** 고친다: 「an opaque `#0a1310` square」 → 투명 타일 + `#2b8e6c` 잉크,
「the 84% ink-width rule」 → 파비콘 75% / 런처 84% 유지. `P10.review`가 그렇게 정했다는 한 줄.

## 4. 문서 (§④) — 코드와 같은 변경에 포함

`frontend/public/assets/README.md`의 **일곱 절**을 §④.1~⑦ 그대로 갱신한다. 그중 둘은 주의:

- **§④.3(함정 절)** — 갇힌 두 섬의 두 번째 좌표를 `(1014,335)` → **`(969,335)`**로. 함정 2의
  본문 문장(「inside 「의」's ㅇ」로 **범위 한정된** 소스 검사)은 **옳으므로 그대로 둔다.**
  그 절에 §1의 두 섬 검사를 파생물 쪽 대응물로 덧붙인다.
- **§④.4** — 「알파 채널이 소스 트림과 바이트 동일」 문장을 **두 조각 이어붙이기 해시** 비교로
  교체. 잉크 픽셀 수 3개는 변하지 않으므로 그대로 두고, 「45열을 잘라도 잉크가 한 픽셀도 변하지
  않는다」가 이 절의 새 주장이다.

§④.1의 바이트수, §④.7의 `sha256` + `identify -format '%#'` 픽셀 서명은 **재파생한 실측값**으로
적는다 — 추정하지 말 것. 심볼과 두 class-B 원본은 무변이므로 기존 해시를 그대로 둔다.

`frontend/README.md:60` — 파비콘 한 줄에 `P10.review` 갱신을 덧붙인다.

## 5. 검증 — 운영자 런타임에서, 진짜 브라우저로

`## Operator Runtime`(`docs/current/operations.md`)이 정한 런타임: `make stack-up` → dev
**`http://127.0.0.1:3010`**, 그리고 **프로덕션 빌드도**(`npm run build && npm run start`, 같은
오리진). 데스크톱 **1280**과 모바일 **390**.

- **워드마크:** 랜딩 nav와 푸터에서 「주주의관제탑」이 **붙어** 읽히는지. h27에서 의\|관 간격이
  약 1.8px 상당. `translateY`가 그대로이므로 세로 위치는 **변하면 안 된다** — 52px 바에서 글자띠
  중심이 26px 선을 물고 있는지 재서 확인.
- **파비콘:** dev·prod 양쪽 DOM에 `link[rel="icon"][sizes="32x32"]` · `sizes="16x16"` ·
  `link[rel="apple-touch-icon"][sizes="180x180"]`. 그리고 **탭에서 실제로 보이는지 — 밝은 탭과
  어두운 탭 양쪽에서.** 투명 타일로 가는 변경의 요점이 바로 그것이므로, DOM에 태그가 있다는
  것만으로는 이 항목이 끝나지 않는다.
- **회귀:** §⑤.6의 여섯 라우트(랜딩 · `/ask` · `/portfolio` · `/stocks` · `/auth` · `/ops`)에서
  nav 마크와 링크 정렬, 푸터 마크, 390px에서 브랜드 + 메뉴 버튼.
- **의견 보내기가 여전히 눌리는지** 한 번은 확인할 것. 워드마크 폭이 3.3px 줄어드는 변경이라
  푸터 기하에 닿을 이유는 없지만, 그 버튼은 이 페이즈에서 **두 번** 죽었다.

브라우저 계측은 **Aside**(MCP 우선)를 쓴다. 쓸 수 없으면 같은 뷰포트·같은 런타임에서 실제
브라우저로 같은 것을 확인하고, **`result.md`에 실제로 쓴 도구 이름을 적는다.** 하지 않은
브라우저 실행을 했다고 적지 말 것.

`npm run typecheck` · `npm run build` · `npm run smoke`.
