## Decisions

- **The empty margin is solved by trimming, and the natural pair is `1213x319`.** The intent
  left this to decomposition. `Wordmark.tsx` renders height-constrained and passes the
  intrinsic `width`/`height` so the browser reserves the right box; the untrimmed 2560x1440
  would reserve a box ~13x too wide and paint the ink at a few percent of it. Trim, `+repage`.
- **The recolor is settled — S1 ran** `-trim +repage -channel RGB +level-colors white,white
  +channel -define png:color-type=6`. `+level-colors white,white` *alone* flattens alpha to an
  opaque rectangle. The `-define` is not cosmetic: without it IM sees all-equal RGB and
  silently writes **GrayscaleAlpha** — pixel-identical, but a different colour type than its
  black sibling. Full command and evidence: the assets README.
- **Provenance has three classes, not one** (S1, in the README): **A** design-project export
  (font + the four `mijual-*`), **B** operator delivery (`juju-logo-source.png`), **C**
  repo-generated derivative (the two wordmarks). "Byte-for-byte from the design project" is A.
- **A derivation is verified by pixels, not file sha256** (S1, measured). IM stamps `png:tIME`,
  so re-running a command gives identical pixels with a different file hash. The README records
  both: file sha256 (the landed file was not touched) and `identify -format '%#'` (the
  derivation). Never "fix" a mismatching file hash by re-deriving.
- **The black variant is for light surfaces only** — conclusion stands, mechanism corrected by
  S1's measurement. The near-white RGB is in the **fully-transparent** pixels (356,503; 54,980
  exactly `#FFFFFF`), not the partial-alpha edge (dark, max R 40). Invisible when composited,
  but non-premultiplied filtering on a ~6% downscale can bleed it into edges: harmless on
  light, would fringe on cosmos. The white variant is immune — every pixel is `#FFFFFF`.
- **The phase takes `accept-gate --require`** (the orchestrator's command to run, not a
  slice's): it changes what the operator sees on every page.

## Operator Questions

- **The ops bar mark — both its string and its treatment.** `components/ops/copy.ts` `OPS_MARK`
  is assumed to become **`주주의관제탑 운영`**; the operator was told and did not object but never
  confirmed it in words. **And the treatment breaks:** `Ops.module.css` `.mark` / `.doorMark`
  render it in `--font-mono` (IBM Plex Mono) with `letter-spacing: 0.08em`, chosen because R7
  called it "an identifier, so it stays raw and mono". IBM Plex Mono has no Hangul, so Korean
  falls back to a system face and the tracking reads wrong on Hangul. (from P10.DECOMP)
- **The favicon: the mark does not reduce.** Verified — rendered at 32px the wordmark is
  illegible mush. There is still no favicon of any kind (no `app/icon.*`, no `favicon.ico`), and
  the assets README's rule forbids substituting, generating or placeholding an image. The
  operator chooses: (a) ship no favicon, as today; (b) supply a square symbol export; or (c)
  authorize cropping the sparkle cluster out of the delivered mark as a symbol. **S2 must not
  decide this.** (from P10.DECOMP)
- **The signed chrome heights may no longer be legible.** R2 signed "h 19px" (nav) / "h 17px"
  (footer). The retired ring's ink filled **75.7%** of its box (14.4px at h19); the new mark's
  Korean wordmark fills only **50.5%** (the sparkle takes the top half), so at the same numbers
  the glyphs render **~9.6px** / **~8.6px**. Raising the height deviates from a signed number;
  leaving it may be unreadable Hangul. The headline thing to look at at the gate.
  (from P10.DECOMP)
- **P4's mail subject still carries the retired name.** The signed R5 spec, quoted in
  `src/mijual/mail.py:14` as the subject `[미주알] {jongmok} — {magamname} D-{n} ({date})`, is
  unimplemented and out of this phase's scope. P4 will render `[미주알]` unless the operator
  re-signs the subject. (from P10.DECOMP)
