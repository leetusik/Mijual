## Context

- **Scope: user-facing only.** Code identifiers stay (`src/mijual/`, `MIJUAL_*`, `X-Mijual-CSRF`,
  the repo dir, both `name` fields, the DB credential, "Mijual Design System") — **but any string
  the product says to a user is in**, Korean inside Python included. Comments/docstrings are
  documentation; the review settled them (see Decisions). The name is uniformly the **unspaced
  `주주의관제탑`** — no spaced variant, **no latin mark**. No design round (finished mark supplied).
- **Operator runtime** — `docs/current/operations.md` `## Operator Runtime`, no `UNFILLED`:
  `make stack-up`; dev `next dev` at `http://127.0.0.1:3000`; Chrome desktop on this Mac + a mobile
  viewport; **and additionally** `npm run build && npm run start`. **`make stack-up` fails at
  `db-up`** — 5433 is held by `changple_web_dev_postgres`, never to be stopped. The way through
  (same image + volume on **5434** via an **`!override`** fragment; `/ops` needs credentials `.env`
  lacks) is now versioned in **`operations.md` § Local Development**.

## Decisions

- **S2/S3 string split, settled at S2.** S2 owned the identity strings bound to the mark
  (`BRAND_ALT_KO`, `COPYRIGHT_KO`, both `metadata.title`s, `OPS_MARK`); S3 the product-name prose.
- **The assistant's own name was a third spelling (S3).** The prompt called the product **미주얼**,
  which the decomposition's `미주알` grep never saw. The prompt decides the name the model *says*,
  so **13 live strings** were swapped (9 `instructions.py`, `tools.py` `DATA_BOUNDARY`, 3
  `declarations.py`). **The latin mark is reworded, never substituted** — there is no romanized
  replacement. `instructions.py` is a signed static cache prefix; only names changed, nothing was
  reflowed, and the one-time invalidation is accepted.
- **Binaries, settled by S1/S2** (`frontend/public/assets/README.md` is the authority): natural pair
  **1213x319**; the white variant is a repo-generated derivative **verified by pixels, not sha256**
  (never "fix" a hash by re-deriving); black is light-surfaces-only; `WORDMARK_WHITE` /
  `WORDMARK_NATURAL`. Re-verified at the review: alpha channels byte-identical (AE = 0), white RGB
  uniformly 255, `-trim +repage` of the source reproduces the black variant, source byte-exact.
- **The phase takes `accept-gate --require`** — it changes what the operator sees on every page.
- **S5 verified the phase end-to-end and fixed nothing**; the review re-opened the product itself
  and every claim held again, in dev and production, desktop and 390.
- **Code doc comments stay as they are (P10.REVIEW, closing S2's note).** Several now *describe*
  rendered output that changed (`chrome/Footer.tsx:15`, `lib/api.ts:2`). They are out of scope by
  this phase's own Context rule, a review may not edit source, and a comment sweep is its own small
  job — **filed as a deferred job**, not left implicit.
- **Dev-tooling banners left unchanged (P10.REVIEW).** `Makefile:1,110`, `compose.yaml:1`. They are
  not a product surface, and the same terminal already prints `mijual-postgres`,
  `mijual:lock:pipeline` and `…/mijual` — all explicitly out of scope — so renaming three banners
  would make the operator's terminal *less* consistent, not more. **Deferred job**, triggered by any
  future identifier rename; named in the walkthrough so the operator is not surprised by it.

## Operator Questions

- **The ops mark's treatment — measured at S2, and it does not hold.** The string is now
  `주주의관제탑 운영` (implemented; the operator was told and did not object but never confirmed
  it in words). `Ops.module.css` `.mark`/`.doorMark` are **untouched** and still set
  `--font-mono` + `letter-spacing: 0.08em`, per R7's "an identifier, so it stays raw and mono".
  What renders (CDP `CSS.getPlatformFontsForNode`, both nodes, dev and production): **IBM Plex
  Mono SemiBold — 1 glyph (the space)**; **Apple SD Gothic Neo SemiBold — 8 glyphs (all the
  Hangul)**. So mono now styles exactly one character. Visible consequences: the 관제탑␣운영 gap
  reads as a double space; the mark's face is the **OS's**, so it differs off macOS; and in the
  bar it sits among Pretendard Korean tab labels and no longer reads as an identifier at all,
  while the `mijual:lock:pipeline free` chip beside it still does. **S2's recommendation, not
  taken:** keep the string, drop `--font-mono` + tracking from those two rules and let
  Pretendard 600 carry it. Signed styling, so the operator decides. (from P10.DECOMP, measured
  by P10.S2)
- **The signed chrome heights — h19/h17 implemented, measured, hierarchy inverted.** Nav
  `<img>` computes to **72.24x19** with a **9.65px** Korean band; footer **64.64x17** with
  **8.63px**. The adjacent nav label is 13.5px and the footer source line 12px, so the mark is
  **0.72x** the type beside it — where the retired ring was **1.07x**. Not illegible (clean at
  retina 2x, no fringing), but the brand is now the smallest text in its own bar. Layout is
  fine: the slot narrows 119.6 → 72.24px, the 24px gap is unchanged, nothing wraps or
  overflows at 1280 or 390. **S2's recommendation, acceptable in one word: `h27` nav / `h24`
  footer** — band 13.7/12.2px, parity with the adjacent type, boxes still narrower than the
  ring's. Raising it deviates from a signed number, so the operator decides at the gate.
  Note also: box-centring puts the glyph band 4.18px below the 52px bar's optical centre (6.14
  at h27), because the ink is bottom-half only. (from P10.DECOMP, measured by P10.S2)
- **The favicon: the mark does not reduce.** At 32px it is illegible mush. **S2 shipped nothing
  and cropped nothing** and confirmed the pre-existing state is intact: no `app/icon.*`, no
  `favicon.ico`, no `manifest`, no `openGraph`, no `icons` key, and zero `link[rel*=icon]` in
  dev or production. The assets README's rule forbids substituting, generating or placeholding
  an image. The operator chooses: (a) ship no favicon, as today; (b) supply a square symbol
  export; or (c) authorize cropping the sparkle cluster as a symbol. (from P10.DECOMP)
- **P4's mail subject still carries the retired name.** The signed R5 spec, quoted in
