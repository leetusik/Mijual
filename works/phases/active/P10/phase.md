## Decisions

- **S2/S3 string split, settled at S2.** S2 owned the identity strings bound to the mark
  (`chrome/copy.ts` `BRAND_ALT_KO` + `COPYRIGHT_KO`, both `metadata.title`s, `ops/copy.ts`
  `OPS_MARK`); S3 owned the product-name prose everywhere else. Both **done**.
- **The assistant's own name is user-facing — and it was a third spelling (S3).** The agent's
  system instruction and tool descriptions called the product **미주얼** (얼, not 알), which
  the decomposition's `미주알` grep never saw. The prompt decides the name the model *says* in
  Korean answers, so it is in scope: **13 live prompt strings** swapped (9 `instructions.py`,
  1 `tools.py` `DATA_BOUNDARY`, 3 `declarations.py`). The product had been shipping two
  spellings of its own name; the rename incidentally normalises that. Comments keep 미주얼.
- **The latin mark is reworded, never substituted (S3)** — there is no romanized replacement.
  `instructions.py:52` `미주얼(Mijual)` lost the parenthesized gloss outright;
  `declarations.py:139` used *Mijual* as an **English noun** and became "this product itself",
  echoing the noun its own first sentence already uses.
- **`instructions.py` is a signed static cache prefix** — its order is a cache key (its own
  header, `:26–36`). S3 changed only names, reflowed nothing; the one-time implicit-cache
  invalidation is an accepted cost.
- **Binaries, settled by S1/S2** (detail: `frontend/public/assets/README.md`,
  `P10.S1/result.md`): natural pair **1213x319** via `-trim +repage`; the white variant is a
  repo-generated derivative (`+level-colors white,white` plus `-define png:color-type=6`, or IM
  writes GrayscaleAlpha) **verified by pixels, not sha256** (IM stamps `png:tIME` — never "fix"
  a hash by re-deriving); the black variant is light-surfaces-only; constants `WORDMARK_WHITE`
  / `WORDMARK_NATURAL`.
- **The phase takes `accept-gate --require`** — it changes what the operator sees on every page.

## Operator Questions

- **The ops mark's treatment — measured at S2, and it does not hold.** The string is now
  `주주의관제탑 운영` (implemented; the operator was told and did not object but never confirmed
  it in words). `Ops.module.css` `.mark`/`.doorMark` are **untouched** and still set
  `--font-mono` + `letter-spacing: 0.08em`, per R7's "an identifier, so it stays raw and mono".
  What renders (CDP `CSS.getPlatformFontsForNode`, both nodes, dev and production): **IBM Plex
  Mono SemiBold — 1 glyph (the space)**; **Apple SD Gothic Neo SemiBold — 8 glyphs (all the
  Hangul)**. So mono now styles exactly one character. Visible consequences: the 관제탑␣운영 gap
  reads as a double space; the mark's face is the **OS's**, so it differs off macOS; and in the
  bar it sits among Pretendard Korean tab labels and no longer reads as an identifier at all,
  while the `mijual:lock:pipeline free` chip beside it still does. **S2's recommendation, not
  taken:** keep the string, drop `--font-mono` + tracking from those two rules and let
  Pretendard 600 carry it. Signed styling, so the operator decides. (from P10.DECOMP, measured
  by P10.S2)
- **The signed chrome heights — h19/h17 implemented, measured, hierarchy inverted.** Nav
  `<img>` computes to **72.24x19** with a **9.65px** Korean band; footer **64.64x17** with
  **8.63px**. The adjacent nav label is 13.5px and the footer source line 12px, so the mark is
  **0.72x** the type beside it — where the retired ring was **1.07x**. Not illegible (clean at
  retina 2x, no fringing), but the brand is now the smallest text in its own bar. Layout is
  fine: the slot narrows 119.6 → 72.24px, the 24px gap is unchanged, nothing wraps or
  overflows at 1280 or 390. **S2's recommendation, acceptable in one word: `h27` nav / `h24`
  footer** — band 13.7/12.2px, parity with the adjacent type, boxes still narrower than the
  ring's. Raising it deviates from a signed number, so the operator decides at the gate.
  Note also: box-centring puts the glyph band 4.18px below the 52px bar's optical centre (6.14
  at h27), because the ink is bottom-half only. (from P10.DECOMP, measured by P10.S2)
- **The favicon: the mark does not reduce.** At 32px it is illegible mush. **S2 shipped nothing
  and cropped nothing** and confirmed the pre-existing state is intact: no `app/icon.*`, no
  `favicon.ico`, no `manifest`, no `openGraph`, no `icons` key, and zero `link[rel*=icon]` in
  dev or production. The assets README's rule forbids substituting, generating or placeholding
  an image. The operator chooses: (a) ship no favicon, as today; (b) supply a square symbol
  export; or (c) authorize cropping the sparkle cluster as a symbol. (from P10.DECOMP)
- **P4's mail subject still carries the retired name.** The signed R5 spec, quoted in
