# Phase P11: Ask agent polish: inline citations and feature cards

_Intent: see [intent.md](intent.md)._

## Objective

Fix two operator-reported defects on the AI 질문 surface. (1) Citation chips break the prose: InlineCitation's always-mounted .quoteWrap is display:grid — a block box in <p class=prose>'s inline flow — so every chip forces a line break and a sentence resting on two or more 근거 renders as 「…입니다.[1] ⏎ [2] ⏎ [3]」. Re-cut the ask chip onto the conditionally-mounted absolute-popover anatomy components/Citation.tsx already ships (R10), so chips follow the sentence's period inline and adjacent chips sit side by side — across all three signed placements (프로즈 · 데이터 행 값 · 계산 입력), on the page and the widget, at desktop and ≤767. Server-side numbering is correct and is not touched. (2) The four hard-coded START_CHIPS_KO cards are all read-a-filing questions, exercising only search_events/get_event and leaving calculate, get_portfolio, save_feedback and get_contact invisible. Replace them with a card set — count freed from D11's 'exactly four' by operator instruction — chosen so that clicking the cards one at a time demonstrates every agent capability, keeping R16's layout and the 'card sentence is the question sent' rule. Lands before P4 so the demo video shows both.

## Decisions

_Durable cross-slice decisions. Replace a superseded line; never stack versions._

- **Q1 — the cards stay hard-coded Korean strings in `components/ask/copy.ts`; no served/derived
  variant.** The frontend's one-way rule (`frontend.md`: a Korean string enters through the surface's
  own `copy.ts` with a citation) already puts them there, and a served set costs an endpoint, a
  loading state and a fallback on the one screen that must never look empty — for nothing the reader
  sees. Aging is handled inside the copy instead: P11.S2 picks companies that are in the corpus
  **now** and confirms each card answers, live, before it finishes. A data-derived set is a
  deferred-job candidate for P11.REVIEW to file, not this phase's work.
- **Q2 — the 의견 card stays, and it files a real feedback row.** `save_feedback` fires only when the
  reader actually offers an opinion, so a card that asks *about* feedback routes to `get_contact` and
  leaves the capability invisible — which is the defect this phase exists to close. The card sentence
  must therefore read as the reader's own first-person opinion, so nothing is filed behind their
  back; the write is the existing anonymous queue row (no new endpoint, no new state, no email).
- **Six cards, one capability each** (2-column grid → three clean rows, no orphan):
  `search_events` · `get_event` · `calculate` · `get_portfolio` · `get_contact` · `save_feedback`.
  `security_check` is not a card (intent.md says why). The final Korean strings are P11.S2's job;
  this mapping is not.
- **R16 D11's two set-level rules survive the count change and bind P11.S2:** every 공시 first
  question carries a 회사 (or 접수번호) — 「이 공시」-style demonstratives only work after a prior turn
  — and the 공시 cards are **different companies × different 권리 가족 × different question shapes**.
  The three non-공시 cards (포트폴리오 · 연락처 · 의견) carry no company and do not breach it: they are
  not 공시 questions and their tools take no filing argument.
- **`D11` in `intent.md`/the objective is R16's *design decision* id** (「D11 · 시작용 질문 카드 4장」,
  `docs/reference/design/rounds/16-smart-assistant/output/result.md`), **not** deferred job D11
  (집계 범위 dates). The design record is immutable and is not edited; the operator's instruction in
  `intent.md` is what supersedes the 「4장」, in the P7 override style.
- **Item 1 is one slice, not two.** The three-placement / two-surface / two-viewport check verifies
  the change P11.S1 itself makes and needs that slice's own context; a second executor could only fix
  what it found by writing the same code again. `P11.REVIEW` re-walks the product for the gate.
- **Chip anatomy: one component, one anatomy** — conditional mount + absolute popover in *both*
  places (R6-4: 「Citation 프리미티브의 인라인형」). Prose: the wrap becomes
  `position: relative; display: inline-block`, as `Citation.module.css` `.wrap`. Row:
  `.citationRow { display: contents }` **stays** and the popover anchors to `.row`
  (`Blocks.module.css`, which takes `position: relative`), so R16 §2.6's 「행 아래, 블록 전폭」 geometry
  is preserved and the measured value-column collapse becomes structurally impossible — an
  absolutely positioned box sizes no grid track. `.quoteWrap` / `.quoteClip` and
  `.citationRow > .quoteWrap` retire with the panel they placed.
- **Order: S1 then S2**, though the two are independent — S1 is the demo-visible defect, and S2's
  live card checks then show correct chips instead of the broken ones.

**(from P11.DECOMP, for P11.S1)**

- **Every element inside the chip must stay phrasing content.** It sits in `<p class=prose>`; a
  `<div>` is reparented by the HTML parser and breaks hydration. `Citation.tsx` L148–151 says the
  same for its own row.
- **The three signed placements are two code paths.** 프로즈 = `Answer.tsx` (~L179); 데이터 행 값 and
  계산 입력 are **one** — `DataRowLine` in `DataBlock.tsx` (`CalcBlock` renders its inputs through it),
  so `place="row"` covers both. Both still get looked at: a `.row` inside `.calc` sits in a
  heavier-bordered block.
- `.citationRow { display: contents }` is **not** the broken case — keep it (see Decisions).
- **Keep everything R16 signed on the chip:** mono 10px, 1px `rgba(95,208,165,.4)`, hover `--live`,
  open `--live-tint`, the 180px 인용 cap, the chip after the sentence's period, and 닫기 = **칩 재탭**
  (R6-4). `Citation.tsx` also offers ×, an outside click and Esc-with-focus-return — adopt them
  deliberately or not at all, but the re-tap close is signed and must survive.
- `inert` retires with the always-mounted panel: an unmounted popover's DART link is unreachable by
  construction, which is what `inert` was buying.
- `.sentence + .sentence { margin-left: .25em }` (Ask.module.css) should start working again once the
  block box is gone — check it, it is part of the defect.
- ≤767 = 44px targets; `Citation.module.css`'s media block is the shipped pattern. `fit()` clamps
  **horizontally only**.
- **Clipping risk to check:** the widget thread is `overflow-y: auto` at 440×620, so a popover opened
  on the last answer can be clipped or extend the scroll. Check the widget's bottom answer.
- **Verification matrix**, in `## Operator Runtime`'s runtime (`make stack-up`,
  `http://127.0.0.1:3010`, Chrome desktop + a mobile viewport) and again in the production build:
