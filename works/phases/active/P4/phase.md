  throwaway profile), five production routes × 1280/390 — ten loads, and the off-origin host set is
  the same on every one of them: exactly `static.cloudflareinsights.com`** (one `GET

  again**, and any *other* off-origin host is still a failure), 첨부2 §4's printed claim now names the

- **UptimeRobot is DROPPED and the probe's cadence is closed by operator decision** (2026-09-02:
  「drop uptime bot and system up checker. just fine if it works now.」). `P4.REVIEW` finding 3 —
  GitHub delivering ~1 scheduled probe run in five hours against a 10-minute cron — is **answered,
  not fixed**: no UptimeRobot monitor is created, no second observer is stood up, and
  `.github/workflows/production-probe.yml` **stays exactly as it is** (no code change in `P4.F2`).
  The accepted cost is that the 결격 window's cover is best-effort: an outage may go unnoticed until
  the operator looks. The re-review must not re-raise this, and its walkthrough must not carry the
  UptimeRobot item.
- **D23 is closed** — `promote-deferred` could not be used (it only *creates* a slice, and `P4.S2` already existed from D7), so it was `P4.S2`'s work and was dropped by hand: it now lives in `works/deferred/dropped/D23/`.
- D32, D35, D37, D19, D22 stay deferred (deploy hardening); D31 lost its trigger.
- **The D-day send is a pipeline stage on its own lock** (`notify`, `mijual:lock:notify`), fired by its own `notify-deadlines` beat entry at **08:30 KST** — an hour after the morning run, and NOT a seventh step of it. Sharing the corpus lock would let a long collection make a notify run skip, and a skipped run writes no `PipelineRun` row, so nobody would get mail and nothing would say so. Being a stage buys the run row (which the ops 개요 joins the beat entry against), the ▷ line, error containment and `once --stages notify` for free.
- **One mail per `(reader, event, lead day, anchor date)`; a 정정 that moves the date is a new deadline and mails again.** Recorded in `notification_send` **after** the transport accepted the message, committed per message. Two chips on one deadline = two mails, deliberately (that is what the reader chose). Accepted cost: `event_id` is an autoincrement, so a full corpus rebuild can repeat one mail per live deadline.
- **No won amount in any mail, ever** — 「확정발행가 전 금액 금지 — 메일에도 동일」 kept structurally: the message payload has no key a figure could travel in, and the 발행가 line states a *state* (확정 / 확정 전 + 확정 예정일). ②/③ carry no price line and no share conversion at all.
- **TLS is required, never opportunistic**: port 465 → implicit TLS, anything else → STARTTLS **refused if not offered**. `SMTP_TLS=none` is plaintext and exists only for a local sink. `SMTP_HOST` unset = the console transport, which is a supported state announced in one startup log line — the product degrades to sending nothing rather than failing to serve.
- **The edge routes EVERYTHING to `mijual-web:3010`, with exactly one special location.** No `/api/` split at nginx (it would change the origin model and break same-origin CSRF), and the one exception is **`location = /api/ask`** — an **exact** match, not a prefix, so it cannot swallow the ordinary buffered `GET /api/ask/start-cards` beside it. It carries the SSE block copied wholesale from `changple-web.conf` `location /bff/`, and — **measured in P4.S3** — it must also **re-declare the two server-level `add_header` lines**, because `add_header` inherits all-or-nothing per context exactly like `proxy_set_header`: without them that route answered with no HSTS and no CSP.
- **Cloudflare: SSL/TLS = Full (Strict) goes FIRST, before the A record is proxied.** A new zone defaults to *Flexible*, and a proxied record under Flexible fetches the origin over http, meets the `:80` → https redirect and loops. Full (Strict) is safe only once the real Origin CA pair is staged (otherwise an instant 526). The whole order is `deploy/runbook.md` R5.
- **The production `mem_limit`s are measured, not placeholders** (P4.S4 dispatch 1, from the box's own
  numbers): `available` 11619 MB with the 22 co-tenants at 5050 MiB, so Mijual's peak concurrent 3840m is
  33% of available. Two moved for a reason — **web 512m → 1g** (hi2vi's directly comparable Next container
  measures 522.7MiB, *above* the old cap; a 512m `mijual-web` was a first-deploy OOM on the very container
  the health gate polls) and **beat 256m → 384m** (the comparable beat measures 156.3MiB and ours imports the
  whole API app). The other five were left alone deliberately — a change without a reason is noise.
- **Corpus seed: seeded ONCE from the dev database, dev accounts KEPT** (operator, 2026-09-02).
  `pg_dump -Fc` of the dev Postgres → `deploy/backups/seed-20260902T013142Z.dump` on the box →
  `deploy/db/restore.sh … --yes` after the stack was up. Production now carries **19 tables ·
  `event` 1359 · `account` 2 · `pipeline_run` 21** — identical to dev, **nothing truncated** — plus

  both the dump and the cache were `rm -P`'d; the dump (reader emails + password hashes) stays on
  the box, 600 inside a 700 directory.
- **`www.jujutower.com`: the alias is ON, and it 301s to the apex** (operator, 2026-09-02: "I want
  www as well"; enabled in `P4.S4` dispatch 3). No re-mint was needed — the Origin CA pair's SAN is
  the wildcard `DNS:*.jujutower.com, DNS:jujutower.com`, and both server blocks load the one
  `jujutower` cert basename, so `validate.sh`/`stage.sh` needed no further edit. **The apex stays
  canonical**; www serves nothing but `return 301 https://jujutower.com$request_uri`. Verified end to
  end through Cloudflare: `https://www.jujutower.com/x?y=1` → **301** → `https://jujutower.com/x?y=1`
  (path and query preserved), and `http://www…` → 301 → `https://www…` → 301 → apex.
- **Nightly backup cron: INSTALL it** (operator, 2026-09-02) — the runbook R7 line at `0 4 * * *`,
  in dispatch 3 after the first real `backup.sh` run. Cron exists with one entry (changple2 certbot

- **Canonicals are PER ROUTE and apex-only, and the root layout deliberately sets no
  `alternates` at all.** `alternates` is inherited *as a whole* by every child segment, so a
  `canonical: "/"` in `app/layout.tsx` would have made every route without its own claim the home
  page — correct-looking on `/` and wrong everywhere else. `lib/seo.ts`'s `routeMetadata()` pairs

  the `noindex` surfaces set none.
- **The `generateMetadata` double fetch does NOT happen — measured, and no React `cache()` was
  added.** One `GET /events/{rcept_no}` and one `GET /stocks/{corp_code}` per page render in

  Next's per-render `fetch` memoization already covers it. A `cache()` wrapper would have been a
  second mechanism for a solved problem.
- **A file-convention `opengraph-image.png` reaches its OWN SEGMENT ONLY** — measured on the first

  a segment that declares no `images`. So the image is declared explicitly, once, as `OG_IMAGE` in
  `lib/seo.ts` and spread into every route (its `.alt.txt` sibling was removed with it — it fed only
  the auto tag). **Do not "simplify" this back to the file convention.**
- **No D-day in any meta description — the date only.** A snippet is cached by a crawler and shown
  for weeks; 「D-7」 is true for one day. The 마감 date does not go stale, so the date is what ships.
  Same instinct as 확정발행가 전 금액 금지, one axis over. (The mail, which is delivered once and read
  immediately, keeps its D-표기.)
- **robots.txt disallows `/api/`, `/ops`, `/auth/`, `/portfolio` AND those surfaces carry
  `noindex, nofollow`** — with one honest caveat recorded rather than papered over: a `Disallow`
  stops the crawl, and a crawler that never fetches a page never reads its `noindex`, so
  `/portfolio` (which **is** nav-linked as 보유 종목) could still get a URL-only index entry. The
  disallow stays the primary control — these are gated or operator-only surfaces and each crawl is a
  full SSR + FastAPI round trip — and the tag is what can get an already-indexed URL removed.
- **`/ops` is a literal in `app/robots.ts`, never an import**, and it appears in `app/sitemap.ts`
  nowhere: R7 names the sitemap explicitly in 「reader chrome 어디에서도 링크 금지」, and
  `components/ops/routes.ts` exists so no shared module can reach an ops path by autocomplete.

  one of them. The sitemap is the only path a crawler has to it, which is the reason the sitemap
  matters here beyond hygiene. Adding a nav link would be a design change.
- **The `/ops` title became `title: { absolute: … }`.** The new root `title.template`
  (`%s | 주주의관제탑`) applies to every child segment, so the panel would have titled itself
  「주주의관제탑 운영 | 주주의관제탑」. `absolute` opts out and keeps the landed string byte-identical.
  The landing does the same for the opposite reason: its own title *is* the site name.
- **The share card is one recorded `magick` command and no new artwork** — `juju2-wordmark-white.png`
  scaled to 720 wide, composited dead-centre on a 1200×630 rectangle of cosmos `--paper` `#0a1310`
  (measured box `720x214+240+208`, opaque, 20,211 white ink px). The 192/512 manifest tiles are the
  R18 favicon recipe at two more sizes. All three re-derive with `compare -metric AE = 0` and
  identical pixel signatures; commands, geometry and hashes are in `frontend/public/assets/README.md`.

- **Postgres and Redis are compose services in production**, on named volumes on the box. The **web container is the only thing the edge sees** — it alone joins `changple_shared_network`; the API, worker, beat, Postgres and Redis live on the project-internal network and do not resolve from the edge (measured, P4.S1). One Python image runs the API, the worker, beat and the schema one-shot, so the worker can never drift from the code whose results the API reads.

- **Uptime monitoring is a GitHub Actions cron probe, not a paid monitor, and it alerts on EVERY
  failure rather than on the green→red transition** (`P4.S6`). GitHub Actions costs nothing on a
  public repo, needs no new infrastructure and already had the credential path; a transition check
  would mean `gh run list` inside the alert path — a second API call that can itself fail or race,
  i.e. a new failure mode inside the one thing whose job is to be reliable. The accepted cost is
  that a real outage mails **every 10 minutes** until it clears. That is deliberate for the 결격
  window. GitHub's own failed-scheduled-run email to the owner stays as an independent second path,
  so a broken SMTP step still surfaces.
- **The probe runs INLINE `curl`, not `scripts/smoke_production.py --light`** — the two checks are
  defined twice on purpose. A monitor must go red only when the **product** is broken; a checkout
  would let a bad commit, a moved file or a Python error turn it red for a reason that has nothing
  to do with the live site, and would add a checkout to ~4,320 runs a month. The duplication is
  three lines of `curl`, and both definitions carry a "change one, change the other" comment.
- **DEPLOY FREEZE — 2026-09-07 11:00 → 2026-09-11 23:59 KST, `deploy/rollback.sh` excepted.**
  `deploy.sh` recreates `mijual-web` for a few seconds and the 결격 rule disqualifies on a single
  outage, so nothing ships in that window; a rollback is a tag flip and stays allowed because it is
  the fastest way back to serving. `P4.S6`'s own redeploy **landed 2026-09-02**, five days before
  the window opens. Recorded in `deploy/runbook.md` beside the two standing no-harm rules. (P4.S6)

  (the same image id, so `mijual-api:previous` now points at that same id) and **only `mijual-web`
