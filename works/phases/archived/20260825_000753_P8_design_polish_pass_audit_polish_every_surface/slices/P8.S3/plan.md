10. **The API — FastAPI, not a Next route.** The repo's rule is that every browser call goes to this app's own origin under `/api/…` and `next.config`'s rewrite forwards `/api/:path*` to the FastAPI origin (`frontend/lib/api.ts` header comment). So the contract's "`POST /api/feedback`" is implemented as **`POST /feedback` on the FastAPI app** (new router `src/mijual/web/routers/feedback.py`, included in `app.py` like the others), reached by the page as `/api/feedback` through the existing rewrite via `lib/api.ts`'s `resolve()`. Body `{message: string}` (trim; empty → 400). Server forwards to vocky exactly per §6: `POST {MIJUAL_VOCKY_API_BASE}/api/feedback`, `Authorization: Bearer {MIJUAL_VOCKY_API_KEY}` — **reuse `src/mijual/web/vocky.py`'s settings names, masked key, no-redirect opener, timeout discipline** (the contract's `VOCKY_API_KEY`/`VOCKY_API_BASE` map onto the repo's existing `MIJUAL_VOCKY_API_KEY` / `MIJUAL_VOCKY_API_BASE`; both are set in the operator's `.env`); payload `{message, source:{product:"mijual"}, recorded_by:"human", channel: "web"|"mobile" (from the request body, set by the entry point), target_type:"surface", session_id?}` (the anonymous session id only if the app already has one handy — do not mint a new identifier for this); unused fields omitted; return **202 `{request_id, accepted_at}`** on vocky 202, 400 on empty, 502-ish failure states for 401/503/timeout mapped to the page's failed state (401 → response tells the client `retryable:false`; log a one-line server warning without the key or the message). Keep this write-only path separate from the `/ops/feedback` agent queue (§save_feedback rule: no merge) — do not write to the conversation store. CSRF: follow whatever the existing anonymous POSTs (e.g. `/ask`) do. One terse pytest for the route with vocky mocked (202 + empty-400 + 401-not-retryable) — keep the suite small; `pytest` stays green.
