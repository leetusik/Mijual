### §3.5 확정된 서비스 겉면 설계 (심사위원 3초 체감 전략)

포지셔닝: "내 계좌 알림 앱"이 아니라 **"시장 전체의 소멸 임박 권리를 감시하는 관제 서비스 + 내 종목 연결"**.

1. **비로그인 랜딩 = 전 시장 권리 관제 현황판** — "지금 소멸 카운트다운 중인 신주인수권 N건, 추정 가치 X억" 헤드라인 + 진행 중 이벤트 보드 + 실시간 카운트다운. 발표 오프닝 숫자("2026년 소멸 신주인수권 총액 추정")가 곧 랜딩이 된다. 방문 즉시 실데이터로 문제의 크기를 체감시킨다.
2. **종목 검색 + 보유량 슬라이더** — 등록·로그인 없이 아무 종목이나 검색하면 "500주 보유였다면 지금 83만 원이 걸려 있고 증서 매도 마감 D-3"를 즉시 환산(오퍼레이터의 미라클 익명 트라이얼 패턴 재사용).
3. **놓친 돈 조회기** — 종목+보유량+기간 입력 → 올해 그 종목에서 놓쳤을 권리 가치 소급 계산. 심사위원이 자기 종목으로 찔러보게 되는 훅.
4. **개인화는 2층** — 포트폴리오 등록·D-day 알림은 체험 후 전환. 심사용 **샘플 포트폴리오 원클릭 로드**(이벤트가 실제 걸린 종목들로 구성) 제공.
5. 확장 서사: 랜딩 체험 → 수동 등록 → 알림 → (로드맵) 마이데이터 자동 연결 → 권리 데이터 MCP 서버(AI 에이전트 정책 현안 접속).

### §3.6 AI의 역할 아키텍처 (유저 반론 ③ "AI가 실제로 뭘 하나? 스크래퍼+웹만 보인다"에 대한 답 — 확정)

프레임: **AI는 '읽기'와 '말하기'를 하고, '계산'만 결정론이 한다.** 스크래퍼는 문서를 가져올 뿐, 문서를 읽는 것이 AI다. 발표 Q&A 1순위 예상 질문이므로 이 절이 서비스 정의서·발표자료에 반드시 들어간다.

**레이어 1 — 읽기: 스키마 기반 LLM 공시 추출 (하중을 받는 코어).**
DART OpenAPI 정형 필드는 뼈대(배정기준일·발행가·비율)까지만 준다. 서비스가 팔아야 하는 필드 — **신주인수권증서 상장 매매기간, 청약 취급 증권사, 실권주 처리 방식, 초과청약 조건, CB 리픽싱 조건·콜풋·보호예수 해제 스케줄, 매수청구 반대의사 통지 방법·기한** — 는 증권신고서·투자설명서 본문 수십 페이지에 서술형으로 흩어져 있다 → 보고서 유형별 스키마 기반 LLM 추출 파이프라인. 특히 **정정공시(기재정정)**: 유증 일정은 수시로 밀리고 가격이 바뀐다. 정정 문서에서 무엇이 바뀌었고 사용자의 D-day가 어떻게 이동했는지 잡는 diff+해석이 상시 AI 작업이다. (▷ 정형/비정형 필드의 정확한 경계는 백로그 1번 스파이크가 확정한다 — 경계가 어디든 위 필드들이 서비스 필수라는 사실은 불변.)

**레이어 2 — 검증: 결정론 게이트가 AI 위에 얹힌다.**
추출 필드마다 산술 정합성(배정비율×주식수 일치 등)·날짜 순서·**원문 인용 스팬 존재**를 결정론으로 검사하고, 불합격 필드는 서비스에 노출하지 않는다(창플 grounding 3중 게이트 + eligibility 이유 코드 설계 이식 — 필드마다 "왜 신뢰 가능한가"의 판정 코드를 갖는다). 심사 서사: "AI를 썼다"가 아니라 **"AI를 통제하며 썼다"**.

**레이어 3 — 말하기: 근거 강제 개인화 생성.**
검증된 구조화 데이터 → "보유 3종목 중 OO에 증서 매도 마감 D-3, 미행사 시 약 83만 원 소멸" 브리핑·알림 문안을 원문 인용 강제 하에 생성. 해설 패널(Q&A)은 이 위의 인터랙션 층.

**심사용 증거물 — 추출 정확도 리포트.** 공시 ~100건 수작업 라벨 평가셋 vs LLM 추출 정확도를 실측 공개(필드별 정밀도, 게이트 차단율 포함). 2025 최우수상이 'RAG 신뢰도'였던 대회 성향 + 오퍼레이터의 실측 문화와 정합. 계산 로직(금액 환산·D-day)은 LLM 무관 단위테스트로 커버.

### §3.7 서비스명: 미주알 (확정, 유저 명명)

**의미 3겹 해석 (발표·랜딩에 그대로 사용):**

1. **관용구 "미주알고주알" = 아주 사소한 것까지 속속들이 캐는 모양.** 이 서비스의 AI가 하는 일 그 자체다 — 증권신고서 수십 페이지 구석의 증서 매매기간·리픽싱 조항·청약 취급처까지 캐내는 §3.6 레이어 1(LLM 추출)의 정확한 이름. 발표 한 줄: **"저희 AI는 공시를 미주알고주알 읽습니다."** AI 역할 설명(Q&A 1순위 질문)이 서비스 이름으로 회수되는 구조.
2. **백로님(backronym): 미리 · 주(株) · 알림.** "미리, 주식의 권리를 알려드립니다" — 서비스의 기능 정의가 세 글자에 들어간다. 가운데 '주'가 주식(株)·주주(株主)로 읽히는 우연이 브랜드의 축.
3. **'알'은 알권리의 계승.** 네이밍 검토 1순위였던 "알권리"의 문제의식(주주의 알 권리)을 '알' 한 글자로 승계 — "주주의 알 권리를 지키는 미주알".

**슬로건 후보:** "공시는 미주알고주알, 권리는 미리 주(株) 알림" / "미리 아는 주주의 권리, 미주알" / 랜딩 경보 기능명은 기존 후보 **"소멸주의보"**를 서브 브랜드로 사용 가능("미주알 소멸주의보").

**표기·도메인:** 영문 표기 **mijual** 확정 — 국어의 로마자 표기법 그대로(미=mi, 주=ju, 알=al)라 "왜 이 표기냐"에 답이 자동으로 되고, 6자로 짧으며 문자열 희소성이 높아 도메인·검색 선점에 유리. 영어 화자가 'visual' 패턴으로 "미주얼"로 읽을 수 있으나 국내 서비스라 실해 없음(오히려 테크 어감) — 로고는 MIJUAL 대문자 + 한글 '미주알' 병기로 각인. 검토 후 기각한 대안: mijooal(발음 충실하나 표기 추함), mizual(visual 라임이나 원명 이탈). **도메인 1순위 mijual.ai**(금융 AI Challenge 출품작이라는 정체성 + AI 서비스 관례), 백업 mijual.kr / mijual.com — 가용성 실사는 백로그 4번에 포함. ⚠ Q&A 대비 한 줄: 사전상 '미주알'의 원뜻(항문 쪽 창자 끝)이 존재하나 대중 인지는 관용구로만 통용 — 어원 질문이 나오면 "속속들이 들여다본다는 관용구에서 왔다"로 관용구 기준으로 답하고 유머로 소화(부정 어감 아님, 순우리말 강점 강조).
