## 1b. 아트워크 교체 — `juju2.png` → `juju2_2.png` (세션 중, 운영자)

운영자가 세션 중 워드마크를 다시 보냈다: **「의」의 카운터(ㅇ 안쪽 구멍)가 뚫려 있지 않았다.**

| | `juju2.png` (첫 전달) | `juju2_2.png` (채택) |
|---|---|---|
| 불투명 근백색 픽셀 | **2,864** | **0** |
| 글리프 밴드 잉크 | 78,570 | **75,731** (−2,839 = 카운터) |
| 밴드 내 잉크 밀도 | 39.4% | **38.0%** |
| 트림 박스 · 종횡비 · 밴드 위치 · 스파클 · 빈 밴드 | \ | **전부 동일** |

**왜 치명적이었나 —** 알파 보존 흰색 리컬러는 불투명 픽셀을 불투명하게 남긴다. 카운터가 불투명 흰색이면 코스모스 다크 크롬에서 「의」의 ㅇ이 **속이 찬 흰 덩어리**로 렌더된다. **검정 변형에서는 정상으로 보이고**(흰 배경에 흰 카운터), 흰 변형에서만 깨진다 — 그런데 제품이 쓰는 것은 흰 변형뿐이다. 파일 목록으로도, 밝은 표면 검수로도 잡히지 않는 종류의 결함이다.

**이 라운드의 수치에 미치는 영향: 없다.** 트림 박스 1292×371 · 종횡비 3.4825 · 글리프 밴드 1132×176 relTop 195 (0.47439) · 스파클 222×165 잉크 2,481 · 빈 밴드 30행 · `INK_OFFSET` 0.26280 — **전부 그대로**. h27/h24와 −7/−6px는 재결정 없이 유효하다.

## 3. Q1–Q7 — 답과 근거

**Q1 (크기) — nav `h27` / footer `h24`.** *운영자 미답 → 세션 결정.*
서명값 h19에서 글리프 밴드는 9.0px, 옆 링크 활자는 13.5px = **0.72×**. h27에서 12.8px = **0.95×** — 마크가 활자의 **동급**이 된다 (폐기된 링은 1.07×). h27은 동시에 **잉크 정렬이 52px 바에서 허용하는 상한**이다: h30이면 박스 상단 여백이 **3.0px**로 떨어져 스파클이 하이라인에 붙는다 (최소 4px 위반). 그리고 운영자는 이 조합을 이미 `var/p10s5/*-h27-*`·`*-h24-*`에서 봤다 — 증거가 있는 유일한 후보였다.
푸터도 같은 대우를 한다 (R2 비율 19:17 = 0.895 → 27:24 = 0.889). 「nav만 키우기」는 버렸다: 두 표면의 마크는 같은 물건이고, 한쪽만 자라면 독자는 두 개의 다른 마크로 읽는다. 이름이 푸터에서 두 번 나온다는 사실은 **배치**가 답할 문제이고 R8이 이미 답했다.

**Q2 (수직 배치) — 잉크 정렬, 스파클 제외. (운영자 답)**
밴드 기하 중심 = 박스 높이의 **76.28%** → 박스 중심 대비 **0.2628·H** 위. nav `translateY(-7px)`, footer `translateY(-6px)` (정수 px로 반올림; PNG는 어차피 7.3% / 6.5%로 리샘플된다).
**렌더에서 확인:** h27 + −7px에서 밴드 중심 **26.10px** (52px 바의 광학 중심 26px), 박스 5.5–32.5px, 스파클 5.5–17.5px. 대조: h19 박스 중심 30.99px · h27 박스 중심 33.10px.

**Q3 (정사각 안의 심볼) — 두 자리 같은 규칙: 잉크 폭 = 박스 변의 84%, 잉크 박스 양축 중앙.** *운영자 미답 → 세션 결정.*
잉크 박스는 **261×216이 아니라 222×165**(§5). 무게중심 광학 정렬은 쓰지 않는다 — 산포 마크라서 무게중심(우상단 별)에 맞추면 좌하단 점들이 박스 밖으로 밀린다. 32px 타일에서 잉크 26.9×20.0.

**Q4 (프레임) — 68×50 프레임과 꼬리 그대로 유지.** *운영자 미답 → 세션 결정.*
Q5가 모션을 폐기하기 때문이다. 토성이 돌던 동안 「이 코너가 살아 있다」를 말한 것은 **움직임**이었다. 움직임을 빼면서 프레임까지 빼면 코너에 **정지한 스파클 하나**만 남는다 — 장식이지 어포던스가 아니다. **꼬리는 이제 이 코너가 대화라고 말하는 유일한 물건**이며, R6에서 두 번째였던 신호가 첫 번째가 된다. 프레임은 히트 하한(32px)도 공짜로 지킨다.

**Q5 (모션 예외) — 폐기. (운영자 답)**
4.5s 밴드 회전 · 14s `ringdrift` · 두 반쪽 링 · `data-motion="tick"` 훅이 전부 사라진다. **제품에 상시 모션이 있는 자리는 이제 없다** — R1의 「no spinners, no ambient motion」이 예외 없이 성립하고, R6 §런처 마크의 운영자 예외 노트는 **토성과 함께 만료**한다.
그 결과 **호버 응답이 색을 진다**: 마크 `#eaf2ed` → `--live`. 프레임 테두리는 이미 호버에서 `rgba(95,208,165,.7)`로 가므로 새 색 발명이 아니라 같은 제스처를 마크까지 끌고 온 것이다. 감축 모드에서 transform은 죽고 **색만 남는다** — 색은 모션이 아니다.

**Q6 (어느 얼굴) — Noto Sans KR.** *운영자 미답 → 세션 결정.*
카드의 한국어는 P10.S7이 실제로 태울 얼굴로 섰다. `MarkScale.html` 하단에 Pretendard 대조 한 줄. 결론: **비율(0.95×)은 두 얼굴에서 같다** — 비율은 `font-size`가 정하고 얼굴이 정하지 않는다. 링크 줄만 2~4px 길어진다. 서체 교체가 크기 결정을 되돌리지 않는다.

**Q7 (1급 심볼) — 예. (운영자 답)**
`components/BrandSymbol.html`이 정본. 규칙: 실잉크 박스 · 84% · 두 색(`#eaf2ed` 쉼 / `--live` 응답, 밝은 표면은 `--ink-1`) · **mask로 칠한다** · 회전·기울임·그림자·그라디언트·별과 점의 분리 사용 금지 · **데이터 표면 사용 금지**(브랜드 물건이 값 옆에 서면 「추정」·「근거」 어휘와 경쟁한다).

## 4. 구현 기법 — 심볼은 `<img>`가 아니라 mask

`background-color: currentColor` + `mask: url(…) no-repeat 50% 50% / 84% auto`. 모양은 알파가, 색은 CSS가 갖는다 → **자산 한 개로 세 색**. 필터 해킹·두 번째 PNG·SVG 재작도 전부 불필요하고, Q7이 요구하는 「어디서든 재색칠 가능한 1급 심볼」이 이 한 줄로 성립한다.
**워드마크는 계속 `<img>`다** — `Wordmark.tsx`의 프로비넌스 논리(픽셀 서명이 그 파일의 유일한 증명)를 mask가 흐린다.

## 5. Departure — 전달 파일에 유령 잉크가 있다 (운영자 판단 필요)

`favicon_and_chatbot_widget.png`의 트림 박스가 **261×216**인 것은 좌하단의 **저알파 조각 두 개** 때문이다:

| 조각 | 위치 | 크기 | 평균 알파 |
|---|---|---|---|
| ① | (52, 257) | 24×21 | **19** |
| ② | (0, 265) | 24×13 | **35** |

합 89px. 실제 마크(별 1 + 점 5)는 **222×165 · 잉크 2,481px**이고, 이는 **워드마크 안의 스파클과 픽셀 수까지 동일**(2,481) — 같은 클러스터, 같은 배율. 즉 **심볼은 정사각이 아닌 것이 아니라 1.345:1이다.**

**알파 보존 흰색 리컬러는 이 유령을 흰 얼룩으로 만든다** (불투명도 7~14%, 코스모스 표면에서 보인다 — 모든 파비콘과 런처의 좌하단). `-trim`으로는 안 지워진다 (알파 > 0). 필요한 것:

```sh
magick favicon_and_chatbot_widget.png -crop 222x165+39+62 +repage \
       -channel RGB +level-colors white,white +channel \
       -define png:color-type=6 juju2-symbol-white.png
```

결정론적이고 기록 가능하며 **모양을 건드리지 않는다** — 이미 승인된 `-trim`과 같은 부류다 (§5 「redraw 금지」와 충돌 없음).

**결정 (운영자 승인 2026-08-31): 이 크롭을 채택한다.** class C 파생물로 기록되고, README에 명령·픽셀 서명과 함께 남는다.

## 6. Departure — 16px 파비콘의 한계 (공개, 미채택 제안 포함)

84% 규칙에서 16px 타일의 잉크는 13.4×10.0이고 **작은 점 다섯은 각 1.4px** — 흐릿한 먼지로 보인다. 이 라운드는 **아트워크를 고르지 않는다**: 16px은 32px 래스터의 다운스케일로 태우고 한계를 기록한다.
**결정 (운영자 승인 2026-08-31): 전체 클러스터의 다운스케일로 간다.** 별 하나만 쓰는 두 번째 크롭(`-crop 74x74+148+12`)은 **채택하지 않는다** — 아이콘 변형이 둘로 갈라지고, 아트워크의 일부를 고르는 선례가 남는다. **아트워크 하나, 규칙 하나**를 유지하고 16px의 부드러움은 기록된 한계로 남긴다.

## 7b. Departure — 코너 예약 84px **+** 데스크톱 「AI 질문」 숨김 (세 번 정정)

이 항목은 **세 번** 틀렸다. 기록해 둔다 — 틀린 방식이 서로 다르고, 세 번째가 제일 위험했다.

| | 주장 | 왜 틀렸나 |
|---|---|---|
| ① | 「충돌 없음」 | 재지 않고 썼다 |
| ② | 「1280 실측 12px 겹침」 | 컨테이너 폭을 **R8 카드**에서 가져왔다. 제품 파일을 읽지 않았다 |
| ③ | 「링크를 숨기면 겹침이 사라진다」 | **`.fin`은 `justify-content: space-between`이다.** 행의 마지막 항목이 항상 내용 우변에 붙으므로, 링크를 숨기면 그 자리를 **「의견 보내기」가 물려받을 뿐**이고 산식은 그대로다 |

**③이 상태를 더 나쁘게 만들었다.** 덮이는 대상이 `AI 질문`(R14 경계에 이름 없음)에서 **`의견 보내기`**(R14 경계가 **이름으로 지목한** 요소, 그리고 `Feedback.tsx`의 380px 패널 앵커)로 옮겨갔다. 덮인 앵커는 미관 문제가 아니라 **죽은 상호작용**이다.

### 산식 (제품 파일에서 읽음)

`app/shell.css` → `.content{max-width:var(--bp-lg)/*1120px*/;margin-inline:auto;padding-inline:var(--space-6)/*24px, ≥768*/}` · `Footer.tsx` → `<div className={`content ${styles.inner}`}>`.

| | 값 |
|---|---|
| 런처 왼쪽 변 | `viewport − 92` (right 24 + 폭 68) |
| 푸터 내용 오른쪽 변 | `(viewport + min(viewport,1120))/2 − 24` |
| **viewport ≤ 1120** | **겹침 68px — 일정** |
| 1120 < viewport < 1256 | `628 − viewport/2` |
| viewport ≥ 1256 | 0 |

세로는 조건 없음: 액션 행 라인 박스 **bottom 24–44.9px** ⊂ 런처 **24–74px**.

### 고침 — 두 조치, 서로를 대체하지 않는다

**① 코너 예약 (기하).** 행의 마지막 항목이 무엇이든 런처를 비껴가게 한다:

```css
.inner{ padding-inline-end: min(84px, max(0px, calc(644px - 50vw))) }
```

검산: 1120 → **84px** (런처 폭 68 = 수학적 하한, + 16px 여백) · 1280 → 4px · **1288 이상 → 0** (뷰포트 자체 여백이 이미 비운다). 어느 폭에서도 겹치지 않고, 넓은 화면에서 행이 열 정렬선에서 밀려나지도 않는다. calc를 피하려면 `@media (min-width:768px) and (max-width:1255px){ padding-inline-end:84px }`가 단순한 등가물이다 (1256–1288 구간의 여백이 16px 미만이 되는 것만 감수).

**② 데스크톱 「AI 질문」 숨김 (중복).** `@media (min-width:768px){ .actionAsk{ display:none } }` — 기하와 **무관한** 별개 근거다: 데스크톱에서 그 목적지는 **nav · 푸터 · 런처 세 곳**에 있었고, R8이 「관제 현황판」 nav 링크를 자른 규칙 **「같은 목적지를 바에서 두 번 말하지 않는다」**(R8 §1)가 그대로 적용된다. ≤767px은 링크 그대로 — 런처가 렌더되지 않으므로 그것이 유일한 진입점이다.

**①만 걸면** 중복이 남는다. **②만 걸면 더 중요한 버튼이 덮인다.** 둘 다 건다.

## 8. 신규 — 런처 focus-visible
