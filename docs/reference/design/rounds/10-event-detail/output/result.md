## 2. walk 14건 — 무엇을 했는가

1. **환산 체인 (390 파손)** — `→` 커넥터를 **폐기**하고 하이라인으로 구획된 계기 셀로 재구성. 데스크톱은 세로 점선, 390은 `grid-auto-flow:row`로 눕고 셀은 `라벨 좌 · 값 우` 2열, 최소 높이 44px. 고아 화살표와 「이론가치→배정비율」 한 줄 압축이 구조적으로 불가능해진다.
2. **`[근거]` / rcept 링크 히트 크기** — 문구는 유지(프로비넌스 잠금 문장이 이 단어를 부른다), 타깃은 데스크톱 32px · ≤767px **44px** (패딩 확대 + 동일 값 음수 마진으로 행 리듬 보존). 인용 패널의 `DART 원문 … ↗`는 모바일에서 전폭 44px 하이라인 행. 열린 상태는 트리거가 든다 — `--live-tint` 채움 + `×` + `aria-expanded`.
2-c. **인용은 오버레이로 (세션 중 운영자 지시)** — 인용 패널이 행 아래로 펼쳐지며 레이아웃을 밀던 것을 **팝오버**로 바꿨다: 불투명 `#0e1a15` + 2px `--live` 좌변, 트리거 기준 절대 위치, 닫기는 팝오버의 `×` · 바깥 클릭 · Esc. 값들의 자리가 움직이지 않으므로 스캔 중 위치를 잃지 않는다. 트리거는 더 단순해졌다 — 상태 표시는 `--live-tint` 채움 하나뿐.
2-b. **인용 밀도 (세션 중 운영자 지시)** — `[근거]`를 **모든 행에 달지 않는다**. 규칙: **화면의 값이 원문의 말과 다를 때만** 칩을 단다 (산문에서 추출한 날짜·수치·비율, 파생값의 입력). 값 자체가 **필러의 문장 1:1**인 행(발행가액 산정방법, 청약 취급처 표, 리픽싱 조건, 콜·풋 스케줄, 통지 방법·접수처)은 인용 패널이 화면의 글을 되풀이할 뿐이므로 칩을 두지 않고, **섹션이 mono `DART 원문 {rcept} ↗` 한 줄로 닫는다** (`.secsrc` · 잠금 문구 재사용 · 32px/44px). 한 페이지의 칩 수가 행 수를 따라 늘지 않는다.
3. **「정정 이력」 상태** — 닫힘 「정정 이력」(R3 잠금) ↔ 열림 **「접기」**(R9 서명 단어 재사용) + `×`, 트리거는 열려 있는 동안 inset 표면 + `--ink-2` 테두리 유지.
4. **정정 전/후 diff** — 화살표 열 폐기, **태그 두 쪽**(정정 전 / 정정 후) 한 문법. 데스크톱 2열 → 390 세로 스택, 같은 마크업. 모든 mono 값 `nowrap` → 「2026-07- / 06」 소멸.
4-b. **헤더 패널 크기 통일 (세션 중 운영자 지시)** — 상태에 따라 헤더 높이가 달라지던 것을 고정한다: 데스크톱 `min-height:136px`, ≤767px/390 `248px` + `align-content:space-between`. 열림 · 닫힘 · 추후결정 · 부재 네 상태가 같은 달력을 차지하므로 이벤트를 바꿔도 아래 본문이 다시 자리잡지 않고, 값이 적은 상태(부재·추후결정)는 행 간격이 벌어져 프레임을 채운다 — 빈 여백이 남지 않는다.
5. **헤더 메타 줄** — 항목은 각각 `nowrap`, 구분점은 뒤 항목의 `::before`. ≤767px에서는 구분점을 전부 끄고 접수번호가 한 줄, 「정정 반영」은 하이라인 칩 → 고아 「·」가 생길 자리가 없다.
6. **닫힌 창의 상태어** — **「기한 지남」**(③의 단계 칩이 이미 쓰는 잠금 단어)을 닫힌 창에 재사용. 규칙표: ① 열림 `거래 가능 · 마감 D-n` · ① 닫힘 `기한 지남` · ② 개시 지남 `진행 중`(「종료」 금지) · ② 개시 전 상태어 없음 · ③ 두 마감 `기한 지남`. 날짜는 어느 경우에도 지우지 않는다.
7. **체인의 인용 문법** — 규칙 하나: **본문 구절이 있는 값만 `[근거]`**. 이론가치는 「추정」(파생값), 배정비율은 무표시(API 티어 — 패널 프로비넌스 줄이 담당). 한 셀에 「추정」과 `[근거]`가 함께 붙는 일은 없다.
8. **② 프로비넌스 티어** — 팩트 스트립을 자기 프레임으로 닫고 **자기 출처 줄**을 준다: `DART 공시 API` · `접수번호 ↗` (mono 10px, inset). 아래 본문 행은 행마다 `[근거]`. 스트립 격자는 `auto-fit` → **3열 × 2행**(390: 1열 6행)로 고정, 「전환 시 주식수」는 부속 문구가 아니라 자기 칸. 두 부분 값(보호예수)은 **값 줄 + 사유 줄**로 분리.
9. **철회 근거 줄** — 한 줄 나열을 끊고 4번의 태그 두 쪽 문법 재사용: `정정사항` 태그 + 항목명 + `[근거]` 머리줄, 아래 정정 전/정정 후.
10. **필드 부재(아시아나)** — 잠금 문구 「현재 버전 공시에 없음」을 **점선 프레임 칩**으로. 실선 StateBadge(추후결정)와 시각적으로 구별 — 두 상태가 다른 사실을 말한다는 것이 보인다. 이유는 여전히 말하지 않는다.
11. **두 목적지 서열** — **환산 = 주**(체인 하단 하이라인 버튼 44px, 390 전폭), **담기 = 부**(헤더 밑줄 텍스트 링크). 둘 다 유지, 서열만 명시. 담기 줄은 마감이 남은 건에만.
12. **제목 의미** — 아이브로가 `h2`(`//`는 CSS `::before`), ③ 단계 제목 `h3`, 정정 밴드 문장 `h2`. 개요: 회사명(h1) → 2단계 절차 / 일정 / 발행 조건 / 정정공시 반영.
13. **질문 스트립** — 배치만: 헤더 패널 하단, 칩 36px(데스크톱) / 44px(390), 가로 스크롤·스크롤바 숨김. 설계는 surface 7 / R14.
14. **390 스택** — 유형칩·회사·(본문 표기)·메타 → 카운트다운 라벨 → D-day → 창 줄 → 담기 → **DART 원문(전폭 44px, `order:9`)** → 질문 스트립 → 환산. R3 모바일 스택에 R5-2의 줄을 끼운 형태로 확정.

## 5. 이탈 기록 (departures)

1. **R3의 체인 화살표 폐기** — R3 §3은 체인을 `→`로 썼다. 390에서 파손되고 데스크톱에서 유도 관계를 잘못 주장하므로 구분자를 하이라인으로 대체했다. R3 §3의 순서·값·「추정」 규칙은 그대로.
2. **② 스트립에 출처 줄 신설** — R3는 스트립 아래 rcept 링크 하나만 두었다. 티어를 말하는 mono 줄을 추가했고, 문구는 sparse 종결 문장의 표현을 재사용했다 (신규 문장 아님).
3. **스트립 격자 고정** — R3의 `auto-fit minmax(150px)`를 3열 × 2행으로. 폭에 따라 4·5칸으로 갈리던 것을 없앤다. 「전환 시 주식수」가 부속 문구에서 독립 칸으로 승격(값의 지위는 변하지 않음 — 표기만).
4. **정정 전/후 화살표 열 폐기** — R3 §CorrectionStory는 「정정 전 / → / 정정 후」 3열이다. 390에서 두 열이 짜부라지므로 태그 두 쪽으로 대체. 필드 무브의 데이터·순서·삭제 문구는 그대로.
5. **③ 2단계 의존 문장 축약** — R3 카드의 「1단계에서 반대의사를 통지한 주주만 행사 가능 — 통지 없이는 청구할 수 없음」에서 뒤 절을 뺐다 (같은 말의 반복). 잠금 문장 `STEP_DEPENDENCY_KO` 자체는 그대로.
6. **Citation 컴포넌트가 자기 CSS를 싣는다** — 미디어 쿼리(44px 하한)를 인라인 스타일로 표현할 수 없어 `<style id="mj-cite-css">`를 한 번 주입한다. 인라인 스타일 원칙에서의 의도적 이탈, 컴포넌트 안에 국한.
7. **재컷의 파급** — Citation 재컷은 조회·해설·정정 스토리 등 모든 사용처에 함께 적용된다 (API 무변경). 다음 슬라이스에서 해당 표면들의 히트 크기가 자동으로 44px 규칙을 만족한다.
8. **버전 레일 행 데이터** — 세기상사 레일은 walk가 실제로 방문한 두 접수번호(20260623000277 · 20260713000345)만 렌더한다. 헤더가 말하는 「정정 3회 반영」의 나머지 버전 접수번호는 그라운딩에 없어 발명하지 않았다 — 실제 화면은 서버의 버전 목록을 그대로 렌더한다.
9. **한화솔루션 확정발행가 인용** — 카드의 인용 문구는 walk 기록의 값(22,100원)을 근거 구절 형태로 옮긴 것이며, 실제 렌더는 payload의 `quote` verbatim이다. 구현 시 카드 문자열을 하드코딩하지 말 것.

10. **행마다의 `[근거]` 폐기** — R3 §4의 「per-field `[근거]` citation」을 세션 중 운영자 지시에 따라 수정했다: 값이 원문과 다를 때만 칩, verbatim 행은 섹션 단위 원문 링크. 프로버넌스는 줄지 않는다 — 모든 값은 여전히 한 번의 탭으로 원문에 닿고, 잠금 프로버넌스 문장도 그대로 유효하다.
