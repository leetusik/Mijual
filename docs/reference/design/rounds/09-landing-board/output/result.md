## 2. P7 잔여 질문 — 결정과 그 이유

- **Q9 (탭 hover)**: 결정 — hover 상태를 준다 (위 13번). 활성 밑줄(--ink-1)과 hover 밑줄(--border-strong)이 달라 두 상태가 겹치지 않는다.
- **Q10 (포커스 하이라인 vs 후보 패널 상단선)**: **변경 없음으로 종결**. P7이 이미 패널의 `border-top`을 없앴으므로
  두 선은 한 선이다. 포커스 링은 입력에만 둔다 — 패널까지 감싸면 목록이 「상자」로 읽힌다.
- **Q11 (481px 경계, SearchRow 44 vs Board 32)**: 결정 — 보드 컨트롤을 **36px(≥768) / 44px(≤767)**로 올린다.
  경계 자체가 사라지고 터치 하한이 행 그리드의 브레이크포인트와 같은 지점에서 바뀐다.

## 3. R2/R3에서 바뀐 것 (supersession)

1. **행 열 계획** — R2의 `86px 1fr 300px 230px 96px` → R9의 `76 · 회사 1fr · 240 · 190 · 96` (extras 없는 목록은
   `76 · 회사 1fr · 300 · 96`): 값 열은 전부 고정폭, 늘어나는 열은 회사 하나. **D-day는 R2대로 행의 마지막 칸**
   (패널 우변에 붙음)이고 구성 요소도 순서도 그대로다. 행 높이 `min-height:44px` + 수직 중앙.
2. **창** — 표시 창 30/+30 (P7 override) → **15/+15**.
3. **창 푸터** — 「356건 펼치기」(남은 수를 버튼에 붙인 형태) → 「15건 더 보기」 + 「남은 371건」 + 「처음 15건으로 접기」.
4. **스트립 토글** — 「펼치기」 고정 라벨 (R2/R3, chrome의 「메뉴」와 같은 논리) → **「접기」와 짝**. 이번 라운드에
   카피가 열렸으므로 「서명되지 않은 라벨」이라는 R2의 근거가 사라졌다.
5. **추후결정 행** — 키 날짜 칸에 라벨 + 빈 자리 → **라벨만**, 상태는 레일. (R3의 「날짜 없음」 규칙은 그대로.)
6. **카운트다운/지표 카드** — 2×2 네 지표 → **3행 세 지표**.
7. **소멸주의보 문장** — `{corp}` 한 종목 고정 → 동시 마감 시 「N개 종목」.
8. **신규 표면 규칙** — 자동 갱신의 보이는 계약 (R2에 없던 층).

## 4. 갱신의 보이는 계약 (요약)

주기는 화면 규칙이 아니므로 이 라운드가 값을 정하지 않았다 (가정 60초, 실제 값은 apply). 화면 규칙:
① 요청 중 아무 변화 없음 ② 새 기준시각이 오면 스탬프 교체 + 「갱신됨」이 다음 갱신까지 유지, 기준시각이 같으면
아무 표시도 없음 ③ 바뀐 행/새 행에 2px --live 인셋 엣지 + 바뀐 값만 200ms 페이드, 다음 주기에 엣지 제거
④ 탭·창(clamp)·펼친 스트립·스크롤·포커스 유지, 사라진 행은 연출 없이 사라짐 ⑤ 문서가 숨겨지면 정지, 다시 보이면 즉시 1회
⑥ 실패는 화면에 문구를 만들지 않는다 ⑦ stale이면 R2 처리 그대로 ⑧ reduced-motion: 페이드 없음, 갱신은 계속.

## 6. 이탈 기록 (departures)

1. **② 행은 값이 네 개뿐이다.** D-day는 R2의 자리를 지키고 값 열은 우변에 붙으므로 CB 목록에서 남는 폭은 종목명 뒤
   한 곳에 모인다. 그 여백을 값으로 채우려면 페이로드를 열어야 하고 (아래 6번), 그것은 새 기능이므로 이 라운드는
   기하로만 답했다.
2. **범례는 새 카피다.** handoff §2-7이 「A legend」를 선택지로 제시했으므로 열린 범위로 읽었다. 네 라벨은 숫자
   표기(mono)이며 새 문장이 아니다.
3. **갱신 주기 미확정.** 화면 규칙은 어떤 주기에서도 같으므로 값은 apply에 남겼다 (가정 60초).
4. **동시 마감 표기는 API 값이 필요하다.** `/board/summary`가 「가장 빠른 청약 마감을 공유하는 건수」를 이미 알지
   못하면 `next_lapse.tie_count` 추가가 필요하다. 그전까지는 종목명을 그대로 둔다 — 화면이 추측하지 않는다.
5. **행 전체 클릭은 stretched link로 구현한다.** 행을 `<a>`로 감싸면 안(`↗`)의 링크가 중첩되므로, 회사명 링크의
   `::after`가 행을 덮는 방식을 택했다. 링크 수·접근 가능한 이름은 오늘과 같다.
6. **CB 탭의 레인은 여전히 넓다 (≈370px).** ② 행이 아는 값은 네 개뿐이고 (`BoardRow`는 필드를 싣지 않는다 —
   `present/board.py`의 명시적 설계), 오버행·전환가액을 행에 실으려면 페이로드 변경 = 새 기능이다. 그래서 남는 폭을
   **행 끝의 한 덩어리**로 모으는 기하만 택했다. 페이로드를 열 의사가 있다면 그때 다시 볼 항목.
7. **그라운딩 팩이 이름을 담지 않은 행은 그리지 않았다.** 랭킹 15행 중 13행, 추후결정 4건 중 1건(경남제약)만 실제
   이름이 있다. 발명하지 않았다. **요청**: 스냅샷 재생성 시 진행 중(②, 지남) 상위 행과 추후결정 전체의 종목명을 포함해 주면
   다음 라운드에서 스트립을 실데이터로 그린다.
8. **카드의 D-day는 walk 기준일(2026-08-23)로 재계산했다.** 스냅샷 표는 2026-08-20 기준이지만, 운영자가 본 화면과
   같은 행·같은 등급을 보여주는 편이 검토에 정확하다 (첫 행 계양전기 D-2, D-9은 흰색, D-40 이상은 dim).
