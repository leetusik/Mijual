# R6 Implementation Contract — grounded 해설 (`P3.S7`)

For the Next.js build (detail delegated to Claude Code per operator note — this is the
binding design contract). Reference cards: `explain/*.html`. **Token delta: none.**

## Surfaces + routes (P3.S7 개정 최종 — 위젯 + 전용 페이지)

- **위젯 챗룸** (데스크탑): 우하단 고정 런처 → 제자리 위젯 **440×620** (화면 폭 ≈1/3),
  `position:fixed` 우하단 (본문 오버레이; 백드롭·dim 없음; 런처는 열리면 숨음, ×로
  닫고 복귀). 배경은 **불투명 `#0e1a15`** — 코스모스 본문이 비치면 읽기 방해 (개정 ①).
  헤더 우측: Lucide `external-link` (= 전용 페이지 리다이렉트, 구 ⤢ 폐기 — 개정 ②) + ×,
  각 28px 정사각. 답변은 메시지 버블. 랜딩 포함 모든 페이지 레이아웃 불변.
- **런처 (클릭 전)**: 챗 메시지 박스형 프레임 **68×50** + 우하단 꼬리 11×11 (45° 회전,
  right 12 / bottom −6), 배경 `#0e1a15`, 1px `--border-strong`, `--panel-glow`.
  안에 22×22 토성 마크 — 상세 스펙 아래 "런처 마크" 절.
- **전용 페이지**: nav 세번째 자리 「AI 질문」 = 페이지 링크. 위젯이 열려 있으면 닫고
  리다이렉트 — 대화·범위 그대로 (같은 sessionStorage 스레드). 위젯 헤더의 external-link
  = 같은 동작. 페이지에는 런처 렌더 금지 (중복 표면 금지). **전용 페이지의 챗 표면은
  프레임 없음** — 패널·브래킷 없이 페이지에 직접, 우측 340 레일만 패널 (개정 ④).
- **모바일 (≤480px): 위젯·런처 없음** — AI 질문 = 전폭 페이지 하나 (메뉴 첫 행 +
  질문 스트립이 열음).
- 상세의 질문 스트립(프리셋 칩 — 그 이벤트의 게이트 통과 필드에서 생성)은 위젯
  (모바일: 페이지)을 이벤트 범위로 열며 질문 전송 — 스트립 자체는 답변을 렌더하지
  않음. 런처·위젯은 vocky 트리거와 모서리 충돌 금지.
- **상태 지속**: 대화 + 범위는 sessionStorage — 위젯↔페이지·페이지 이동에 살아남고
  탭 닫으면 화면에서 사라짐. 스트리밍 중 이동/전환에도 끊김 없음.
- **범위 모델**: 이벤트 상세에서 열면 범위 = 그 이벤트 (헤더 칩 `범위: {종목} ·
  {rcept_no}` + ×로 전체 공시로 해제); 그 외 = `범위: 전체 공시`. 범위 전환은 새
  질문부터 적용 (기존 답변 불변).
- 완전 익명, 게이트·가입 유도 없음. 계정 로그인 여부와 무관하게 동일 동작. 대화는
  서버에 익명 로그로 저장됨 (운영 관제 패널 열람) — 카피는 이를 숨기지 않음.

## Agent (fully functional — operator note)

- **Tools** (server-side, agent가 호출하고 UI는 결과를 사실 행으로 표시):
  `search_events(query)` → 이벤트 목록/단건 (corpus 검색), `get_event(rcept_no)` →
  검증 계약 (exposable 필드 + quote/span/rcept_no), `get_portfolio()` → 세션/계정/샘플
  포트폴리오 + 상류 계산 D-day·금액, `save_feedback(text, email?)` → 운영자 대기열
  자동 저장, `get_contact()` → 운영자 연락처 (문자열 미정 — 운영자 지정; 발명 금지).
- **도구 행 렌더**: mono `--text-xs` `--ink-3`, 좌측 2px `--border-soft` hairline —
  모바일에서도 생략 금지. 형식: `이벤트 검색 「{q}」 → {n}건 · {유형} · {rcept_no}`.
- **에이전트는 절대 계산하지 않음** (§3.6): 모든 수치는 도구가 돌려준 검증 계약 값
  그대로 — D-day·환산·금액을 프롬프트/모델에서 산출 금지. 파생값은 「추정」 태그 유지.
- **인용 강제**: 사실 주장 문장마다 근거 칩. 검증된 span 없는 주장은 생성 단계에서
  차단 (스트림에 나올 수 없음). 인용문 재구성·요약 금지 — verbatim span만.
- 검색 0건: "「{q}」에 해당하는 공시를 찾지 못했습니다" + 관제 현황판 링크 — 추측 금지.

## 인라인 인용 (R6-4)

- 번호 칩: mono 10px, `--live` 잉크, 1px rgba(95,208,165,.4) 테두리, 같은 근거 = 같은
  번호. 탭 → 제자리 인용 블록: `--surface-inset` + 좌측 2px `--live`, verbatim quote +
  `DART 원문 {rcept_no} ↗`. 닫기 = 칩 재탭. Citation 프리미티브의 인라인형 — 블록형과
  스타일 공유.
- API-tier 사실 (quote 없음): 블록에 "DART 공시 API 수치 — 원문 스팬 없음, 접수번호가
  인용 핸들" + 링크 (R3 규칙).
- 답변 푸터: `근거 N건 · {rcept_no} · {생성시각 KST}` + 컨텍스트 링크 (필드로 이동 /
  이벤트 상세 / 다시 질문).

## SSE (스트리밍)

- 상태: idle → **답변 준비 중** (버튼 텍스트 교체 + disabled — 스피너·점 금지) →
  **스트리밍** (프로즈 자람 + 캐럿 7×15px `--live`, 1s steps(1) 블링크,
  reduced-motion 정지; 중지 버튼) → **완료** (푸터 페이드 인, `--dur-base`) →
  **중단/오류** (부분 답변 유지 — 지우기 금지, `--ink-2`로 감쇠; inset 행 "연결이
  끊겼습니다 — 답변이 여기서 중단되었습니다." + 재시도).
- 인용 칩은 해당 주장과 동시에 도착 (span 검증 완료분만) — 자리표시 칩·후행 부착 금지.
- 모션: 페이드만. 버블 슬라이드·타이핑 점·스피너 금지.

## 거절 (R6-7 — 오류 상태 아님)

- 렌더: 일반 답변과 같은 프로즈 (alert 색·아이콘 금지). 구조 3단: ① 상태 사실 (잠긴
  카피 우선 — `이 유상증자는 철회되었습니다`, `해당 항목이 공시 본문에 없습니다`) ②
  거절 문장 (result.md의 가족) ③ 갈 곳 링크 (DART 원문 rcept_no verbatim · 이벤트
  상세 · 내 종목 조회).
- 철회 사실 등 검증된 상태에는 근거 칩을 붙임 — 거절도 인용 강제 대상.
- reason code별 문구 생성 금지 — 카테고리 5종 (철회 · 확정 전 · 공시에 없음 · 검증
  미통과 폴백 · 계산 요청)만. 계산 요청 → 조회 리다이렉트 문장 고정.
- 확정 전 금액 질문: 아는 사실(확정 예정일 등)은 인용과 함께 말하고 금액만 거절.

## 세션 + 저장 (R6-5·6 개정)

- **질문 수 무제한** — quota·"남은 질문 N회"·소진 상태는 어느 표면에도 없음 (R6-5의
  quota 조항 폐기, 개정 ③). 완전 익명은 유지: 로그인 게이트·가입 유도 없음, 계정
  로그인 여부와 무관하게 동일 동작. 서버 레이트 리밋은 운영 사안 — UI 카피 없음
  (남용 차단이 필요하면 R7 운영 관측과 함께 별도 결정).
- 화면 지속성은 sessionStorage — 페이지 이동에 살아남고 탭 닫으면 화면에서 사라짐.
  localStorage 사용 금지 (R5 포트폴리오와 다른 규칙임에 주의).
- **서버 저장은 있음 (R6-6 개정)**: Q&A 이력은 DB에 익명 로그로 저장되고 운영 관제
  패널에서 열람 (품질·거절 사유 점검). 계정·PII와 연결 금지. UI 카피는 「대화는
  익명으로 저장됩니다 (품질 점검용)」 — "저장 이력 없음"·"탭 닫으면 사라집니다" 금지.

## 의견 · 문의

- 의견: 자유 텍스트 → 자동 저장 (`save_feedback`), 확인 "의견을 저장했습니다 —
  운영자가 확인합니다." + 선택 이메일 입력 (답장용). 실패 시에만 재시도 행.
- 운영자 문의: 연락처 문자열은 배포 설정값 — **미정, 운영자 지정** (하드코딩 발명 금지).

## 런처 마크 (개정 ⑤ + this session)

- 마크 = 22×22 토성. **행성**: 22px 원, `#dfe9e4`, `overflow:hidden`; 자전 밴드 =
  `repeating-linear-gradient(90deg, rgba(30,52,42,.34) 0 2px, transparent 2px 7px)`
  `background-size:14px 100%`, x축 −14px 루프 4.5s linear infinite.
- **링은 두 반쪽 (this session 수정 — 앞뒤 통과)**: 같은 박스 두 개
  (`left:-9px; top:5px; 40×13; border:1.5px solid rgba(95,208,165,.9); border-radius:50%`),
  하나는 행성 **앞**(DOM 뒤) `clip-path:polygon(0 49%,100% 49%,100% 100%,0 100%)`,
  하나는 **뒤**(DOM 앞) `polygon(0 0,100% 0,100% 49%,0 49%)`. 두 반쪽이 동일
  `ringdrift` 14s ease-in-out infinite (`rotate(-19deg)↔rotate(-13deg) scaleX(.94)`)를
  공유해 한 개의 링으로 읽힘. **한 겹 링을 행성 위/아래 한쪽으로만 깔지 말 것** —
  평면 스티커로 읽히던 최초 버그.
- hover: 프레임은 고정, **마크만** `scale(1.35)` (`--dur-base`), 프레임 테두리
  `rgba(95,208,165,.7)` + 배경 `#122219` (꼬리도 함께). active: `scale(1.15)`.
  열림 상태: 마크 페이드아웃 + × (16px, 1.5px 바 ±45°).
- `prefers-reduced-motion`: 밴드·드리프트·전환·hover 확대 전부 정지.
- **모션 규칙 이탈 기록**: R1의 "no spinners/no ambient motion"은 데이터 표면 규칙 —
  브랜드 런처 마크에만 예외 (operator 지시). 데이터 표면으로 번지지 말 것.
- 후보 비교 카드: `explorations/widget-launcher-marks.html`
  (⏳ P3.S7 · Explain / "런처 마크 후보 6") — 채택안 = **현재(밴드+링) + 앞뒤 링 수정**.

## Hard rules (restated)

인용 없는 주장 — 금지. 인용문 재구성 — 금지. 에이전트/브라우저 계산 — 금지 (D-day
포함, KST 상류만). 「추정」 없는 파생값 — 금지. 확정 전 금액 — 금지. 익명 경로 차단 —
금지. 게이트 실패 데이터로 답변 — 금지 (거절 가족으로). 가짜 Q&A 이력 (지난 대화 목록 UI) —
금지 (서버 저장은 하되 사용자 표면에 이력 UI 없음). quota·"남은 질문" 표기 — 금지. 스피너·타이핑 점 — 금지. 거절에 alert 색 — 금지.
