## 1. 이벤트 어휘 (표면이 가정하는 것)

**추가만 한다.** 새 필드/이벤트는 비어 있으면 실리지 않으므로 `lib/ask.ts`의
`switch (frame.event)`와 두 시야는 빌드 중에도 계속 동작한다.

모든 구조화 이벤트는 **`block_id`**(턴 내 안정 식별자)와 **`persistent: bool`**를 갖는다.
같은 `block_id`의 후속 이벤트는 **추가가 아니라 제자리 교체**다.

| 이벤트 | 필드 | 지속성 |
| --- | --- | --- |
| `StatusEvent` | `phase: read\|search\|open\|calc\|write` | **transient** — 저장 안 함. 항상 **하나만** 살아 있고 다음 phase가 교체한다. 첫 `TextEvent`에 소멸 |
| `DataBlockEvent` | `block_id`, `title: str\|None`, `rows: [{label, value, citation: int\|None, reader_input: bool}]` | persistent |
| `CalcBlockEvent` | `block_id`, `mode: verified\|expr`, `name`, `inputs: [동일 row 스키마]`, `expr: str\|None`, `result: str\|None`, `state: pending\|done\|error`, `why: str\|None` | persistent. `pending` → `done\|error`가 **같은 `block_id`로** 도착 |
| `TextEvent` (확장) | + `unverified: [(start, end)]` — 문장 내 문자 오프셋 | persistent |
| `RefusalEvent` (확장) | `family` ∈ 6값 화이트리스트 (보안 포함) | persistent |
| `ToolRowEvent` | **변경 없음** — 행 문자열 verbatim | persistent |
| `TurnEnd` (의미 변경) | `blocked`는 **삭제된 문장 수가 아니라 제거된 마커 수**. `reason=round_budget\|tool_budget\|call_budget`이면 표면이 소진 끝맺음을 그린다 | — |

**도구 흐름은 새 이벤트가 아니다** — 기존 `ToolRowEvent`들의 클라이언트 측 묶음이다. 접힘 요약의
두 수: `tools` = 그 턴의 도구 행 수, `events` = 그 턴이 **읽은 서로 다른 접수번호 수**(서버가
이미 아는 값; 없으면 도구 행에서 파싱하지 말고 `TurnEnd`에 실어 보낼 것).

**저장 (계약 확장 1/2).** `web/ask.py::_Released.absorb`와 `conversationstore.record_turn`은
`DataBlockEvent`/`CalcBlockEvent`의 **페이로드를 그대로** 저장한다. 프로즈로 환언하지 않는다 —
계산의 감사 경로(입력 + 각 입력의 근거 + 식)는 프로즈에 존재하지 않으므로 환언은 곧 유실이다.
`StatusEvent`는 저장하지 않는다.

**거절 어휘 (계약 확장 2/2).** `REFUSAL_FAMILIES`에 `보안` 추가, 은퇴한 두 값은 **읽기 전용으로
잔존**(과거 행). `frontend/components/ops/copy.ts::REFUSAL_CATEGORIES_KO`도 같은 6값.

**보안 하드 리젝트 위치.** `loop.run_turn`에서 `model.stream(...)`이 반환하고 `calls`가 수집된
직후, `_execute` **이전**. 그 라운드의 도구를 하나도 실행하지 않고, `ModelMessage`를 추가하지 않고,
`RefusalEvent(family="보안")`를 내고 턴을 종료한다. 모델에 두 번째 기회를 주지 않는다.
로깅: **카테고리 + 200자 발췌 + session_hash**, 로그 전용 (DB 없음).

## 2. 요소 사양

CSS는 `ask/r16-ask.css`에 완성형으로 있다 (토큰만 사용, 신규 토큰 0건). 클래스 이름은 참조용이고,
제품에서는 기존 CSS Module 관례를 따른다. **수치는 그대로 옮긴다.**

### 2.1 StatusLine (transient)
- 한 줄. mono `--text-xs` ink-3. 왼쪽 테두리 **2px dashed `--border-soft`** + `padding-left 8px`.
  (도구 행은 2px **solid** — 실선 = 남는 사실, 점선 = 지나가는 상태.)
- `nowrap` + 가로 스크롤(스크롤바 숨김). `role="status"`.
- 자리: 답변 상자의 **마지막** 자식(푸터·끝맺음 앞). 항상 1개. phase가 바뀌면 텍스트만 교체.
- 첫 `TextEvent`가 오면 제거. **애니메이션 금지** (스피너·점·페이드 없음).

### 2.2 ToolTrace
- 행은 `ToolRowEvent` verbatim, 오늘의 도구 행 스타일 그대로(한 줄 + 가로 스크롤, 접수번호 줄바꿈 금지).
- `rows.length <= 3` **또는** 스트리밍 중 → 전부 평평하게 펼침.
- `rows.length >= 4` **그리고** 턴 완료 → 한 줄 요약(`trace(tools, events)`) + `자세히`.
  펼치면 각 행 앞에 mono 순서 번호(ink-3, `margin-right 8px`).
- 접힘/펼침은 표면 상태이며 저장되지 않는다. 저장은 언제나 전체 행.
- 요약 줄 왼쪽 테두리 2px solid(도구 행과 동일). `자세히/접기` 타깃 32/44px.

### 2.3 DataRow
- 블록: 1px `--border-soft`. 머리말 = mono 11px ink-3, 기본값 `DATA_HEADING`, 서버가 title을
  주면 그것을 쓴다. 머리말 없음도 허용(`title: null`).
- 행: **세 칸** `grid-template-columns: minmax(0,40%) minmax(0,1fr) auto` (≤767: 36%), `column-gap 8px`,
  패딩 `8px 12px`, 행 사이 1px dashed. 라벨 = sans `--text-sm` ink-2 `word-break:keep-all`.
  값 = mono `--text-sm` tabular-nums ink-1, **`nowrap` + 값 칸만 가로 스크롤**.
- 셋째 칸(고정, `nowrap`): `reader_input`이면 「입력」 마커(ink-3), `citation`이 있으면 인용 칩
  (프로즈의 칩과 **같은 컴포넌트**). **칩은 값과 함께 스크롤되지 않는다** — 390에서 긴 값이 있을 때
  칩이 화면 밖으로 밀리면 근거가 사라진 것과 같다.
- 블록은 `.aa`(flex column)에서 `align-self:stretch`로 폭을 얻는다. `width:100%`를 쓰면 ≤767의
  전폭 규칙(`margin-inline:-12px`)이 폭을 늘리지 못하고 블록만 왼쪽으로 밀린다.
- `rows.length > 6` → 6행 + `모두 보기 (N)` / `접기`. 타깃 32/44px.
- ≤767: 블록 `margin-inline: -12px` (답변 상자 패딩 밀어내기).
- **3열 이상 표는 만들지 않는다.**

### 2.4 CalcBlock
- 블록: 1px **`--border-strong`** (데이터 행보다 한 단 무겁다).
- 머리말: mono 11px — `--live` 색 단어(`검증된 계산` | `식 계산`) + ink-3 이름(예: 초과청약 한도).
- 입력 행: DataRow와 **같은 행 스키마·같은 CSS**. 독자가 준 값 = 「입력」 마커(칩 없음),
  공시에서 온 값 = 인용 칩.
- 식 줄: mono `--text-sm` ink-2, `nowrap` + 가로 스크롤. `state=error`면 그리지 않는다.
- 상태 (같은 `block_id`에서 제자리 교체, 블록이 뛰지 않게 결과 행과 진행 줄의 자리는 하나):
  - `pending` → 「계산 중」 한 줄 (mono 11px ink-3).
  - `done` → 결과 행: 배경 `--live-tint`, 왼쪽 「결과」(12px ink-2), 오른쪽 값 = **`--text-md`
    mono 600 `--live` + 「계산」 마커**.
  - `error` → `calcError(why)` 문장 (sans `--text-sm` ink-2). **alert 색·아이콘 금지.**
- 블록은 도구 호출 시점에 **입력만이라도** 먼저 나타난다 (감사 가능성의 절반).
- 계산 결과는 **푸터의 「근거 N건」에 세지 않는다** — 근거 수 = 칩 번호의 수(R14 유지).

### 2.5 마커 가족 (배타적 3종)
`추정`(기존, `--text-est`) · `계산`(신규, `--live`) · `미확인`(신규, ink-2).
기하는 셋 다 `EstimateMarker` 그대로: `.56em` / `vertical-align .22em` / `padding .1em .5em` /
`margin-left .55em` / `1px color-mix(in srgb, currentColor 42%, transparent)` /
`letter-spacing .08em`. 값은 mono 600 tabular-nums nowrap.
- **미확인** = `TextEvent.unverified` span의 렌더. 문장은 살아남고(strip-don't-drop) 수치만 표시된다.
  **턴을 고정 문장으로 교체하지 않는다** (Q-B: 클레임 단위).
- 마커도 칩도 없는 숫자는 존재해서는 안 된다. 서버가 span을 못 만들면 **문장을 지우지 말고**
  그대로 내보내고, 그 사실을 `TurnEnd`에 계수로 남긴다.

### 2.6 인용 칩
**변경 없음** (mono 10px · `rgba(95,208,165,.4)` 테두리 · hover 시 테두리 불투명 `--live` ·
열림 `--live-tint` · 인용 블록 180px 캡 · API-tier는 링크만 · ≤767 타깃 44px).
미리보기 **미채택**. 새로운 것은 칩이 붙는 **자리**뿐: 프로즈 + 데이터 행 값 + 계산 입력.
- **문장 부호:** 칩은 문장의 **마침표 뒤**에 온다 (`…있습니다.` + 칩). 문장은 칩 없이도 완결되어야 하며, 마커가 제거될 때 마침표가 함께 사라지지 않는다.

### 2.7 소진 턴
- 부분 답변 유지 + `data-dim` (프로즈 ink-2) — R14 중단과 동일 처리.
- **inset 없음 · 버튼 없음 · 신규 문자열 없음.** 소진의 표식은 감쇠된 프로즈와 접힌 도구 흐름뿐이다.
  (`.astop` inset은 R14의 「연결이 끊겼습니다 …」 = 연결 끊김 상태 전용으로 남는다.)
- 입력창에 아무것도 자동 입력하지 않는다 (좁힌 질문 제안 = 추천 = Q-A 위반).
- 도구 흐름은 대개 4행 이상이므로 접힌 상태로 도착한다.

### 2.7b `/ask` 페이지 구조 (레일 없음)
- 열 하나: `max-width 760px`, `margin-inline auto`. 오른쪽 열 없음, sticky aside 없음.
- **빈 상태:** 페이지 세로 가운데(`min-height 560px`, ≤767 420px)에 폭 640 블록 —
  `START_HEADING_KO`(`--text-2xl`, ≤767 `--text-xl`) → `AGENT_INTRO_KO`(`--text-sm` ink-2) →
  **컴포저** → 시작용 **질문 카드** 5장. **익명 줄 없음** (표면 어디에도 없다 — R6-5의 성질은
  기능으로 지켜지고 카피로 선언되지 않는다).
- **정렬:** 시작 화면은 가운데 정렬(입력 텍스트와 카드 안의 질문만 왼쪽 정렬).
- **질문 카드:** 2열 그리드(≤767 1열), 카드 = `--surface-raised` + 1px `--border-soft`,
  최소 높이 56px, 패딩 12px, sans `--text-sm` ink-1, hover 시 테두리 `--live`.
  마지막(제품 메타) 카드는 두 열을 차지하고 배경 없이 ink-2 — 질문이 아니라 안내이므로 한 단 낮다.
  누르면 카드의 문장이 그대로 전송된다.
- **컴포저:** 감싸는 테두리·그림자 없음(입력창 자신의 1px만 — 이중 프레임 금지),
  `/ask`에서는 `border-top` 구분선도 없음. 위젯 컴포저의 R14 기하는 그대로.
- **대화 상태:** 스레드가 열을 채우고 컴포저는 하단 sticky(`.abar`, 배경 `--paper`).
- **새 대화:** 스레드가 있을 때만 존재한다 — 시작 화면에는 그리지 않는다(비울 것이 없다).
  대화 중에는 열 오른쪽 위에 sticky(`.atop`, 배경 `--paper`), mono `--text-xs` ink-2 밑줄,
  32/44px 타깃. 스레드를 비우는 동작만 — 이력 목록·제목·복원을 만들지 않는다(R6 금지 유지).
- **답변 푸터:** `다시 질문`은 폐기(2026-08-25). 푸터는 `근거 N건` + 접수번호 + KST 스탬프 +
  `이벤트 상세`(오른쪽 끝)까지다. 재시도는 중단 턴에만 남는다.
- 이벤트 상세에서 위젯을 열 때 그 공시의 프리셋 스트립(R14)은 그대로 쓴다. `/ask` 시작 화면의
  칩은 위 5개다.

### 2.8 배치 (두 시야 공통 — 포크 금지)
답변 상자의 자식 순서: **도구 흐름 → 구조화 블록(서버 순서 그대로) → 프로즈 → 링크 →
진행 표시 / 끝맺음 → 푸터.** 간격은 `.aa`의 `gap 12px` 하나. 블록은 항상 전폭이며 나란히 놓이지
않는다. 폭이 바꾸는 것은 값 칸 스크롤 여부와 ≤767의 `margin-inline: -12px`뿐.

## 3. 프롬프트/루프 변경 (표면이 의존하는 부분만)

1. `_CITATIONS` 중간 3분의 1 재작성: 「마커 없는 문장은 독자에게 도달하기 전에 폐기된다」 →
   「인식되지 않는 마커는 **제거되고 문장은 남는다**」. 인용 강제는 **공시 사실 문장에만** 걸린다.
2. `_NEVER_COMPUTE` → 계산기 안내로 교체. `HOW TO WRITE A FIGURE`(`value_display`)는 유지.
   **브라우저·프론트엔드 계산 금지는 유지된다** — 계산은 도구만 한다.
3. `_refusal_block()`: 4가족(철회·확정 전·공시에 없음·보안)으로 재작성. 「범위 밖은 거절이 아니다」를
   명시.
4. `FINALLY`: 두세 문장은 **상한**이라고 다시 쓰고, 인사·짧은 확인·메타의 예외를 **두 번** 적는다
   (범위 절과 인용 절 양쪽) — S1의 「한 문장을 두 번 말한다」 소견 그대로.
5. 정적 규칙서를 먼저, 턴마다 바뀌는 값(SCOPE·오늘(KST))은 **맨 뒤로** (P3; 캐시 프리픽스).
   `client.Usage`에 cached-input 필드를 추가해 ▷ 원장에서 효과가 보이게 한다.
6. `search_events → 0건`은 지금처럼 **도구가 서명된 문장을 사실로 반환**하는 경로를 유지한다 (P8).
7. `max_model_calls ≥ max_rounds`를 유지 — 세 수치는 함께 올린다.

## 4. 회귀 체크리스트 (카드가 그린 상태 = 검증 항목)

1. 「안녕」 → 인사 한두 문장. 도구 행 0 · 칩 0 · 푸터 없음 · **거절 아님**.
   인사는 독자가 보고 있는 화면을 **언급하지 않는다** (에이전트에게 그 정보가 없다).
2. 「주식 처음인데 뭐부터 사면 좋아요?」 → 한 줄 거절 + 갈 곳. `RefusalEvent` **미발생**,
   저장된 거절 가족 없음.
3. 인용 마커가 잘못된 문장 → 마커만 사라지고 문장은 남는다. 선행 공백도 함께 정리된다.
4. 「1,000주면 초과청약 몇 주?」 → 계산 블록: 입력 2행(하나는 「입력」 마커, 하나는 칩) ·
   식 한 줄 · 결과 「200주 계산」. 푸터 「근거 2건」(칩 수).
5. 계산 진행 → 완료: 같은 `block_id`가 제자리 교체되고 **블록이 뛰지 않는다**.
6. 확정 발행가액 미공시 상태에서 금액 계산 요청 → 계산 블록 `error` + 「확정 전」 가족 문장.
   alert 색 없음.
7. 데이터 행 7행 → 6행 + 「모두 보기 (7)」, 누르면 전부 + 「접기」.
8. 발행가액 산식 같은 긴 값 → 값 칸만 가로 스크롤. 블록 폭 불변, 줄바꿈 없음, 접수번호 무손상,
   **칩과 마커는 항상 보인다**(스크롤되지 않는 셋째 칸).
8b. 390에서 데이터·계산 블록은 답변 상자의 좌·우 끝까지 닿는다(양쪽 여백 0, 오른쪽에 24px 틈 없음).
9. 도구 행 3개 → 평평. 4개 이상 + 완료 → 「도구 N번 · 공시 M건 읽음」 + 자세히. 스트리밍 중에는
   4개 이상도 펼침.
10. 진행 표시: 한 번에 한 줄, phase 교체 시 스레드 높이 변화 없음, 첫 토큰에 소멸, 저장 안 됨.
11. 주입 시도 → 「보안」 가족 문장만. 도구 실행 0 · 인용 0 · 링크 0 · 점검 언급 0 ·
    같은 턴에 추가 프로즈 0. 로그에 카테고리 + 200자 발췌 + session_hash.
12. 예산 소진 → 부분 답변 감쇠 유지, **끝맺음 문장·버튼 없음**. 「예산·한도·라운드」라는 말이
    화면에 없고, 연결 끊김의 inset이 잘못 나타나지도 않는다.
13. 도구가 확인하지 않은 공시 수치가 프로즈에 있으면 → 「미확인」 마커. 문장·턴 모두 살아 있다.
14. 390: 블록 전폭, 값 무손실, 칩·자세히·모두 보기 타깃 44px, 위젯·런처 부재.
15. 1440: 두 열 `minmax(0,760px) 340px` 유지, 레일 sticky, 블록은 넓어지되 나란히 놓이지 않는다.
16. 대화 로그 재생: 데이터 블록과 계산 블록이 **원형 그대로** 복원된다 (입력·식·결과·각 입력의 근거).
17. `prefers-reduced-motion`: 새 요소에는 애니메이션이 없으므로 차이가 없어야 한다. 캐럿만 정지.
18. 위젯과 페이지가 같은 턴을 **같은 블록 구성**으로 그린다 (스토어 포크 없음).
19. 헤더 어디에도 「범위:」 칩이 없다. 특정 공시 상세에서 위젯을 열어도 헤더는 두 아이콘뿐이고,
    그 공시의 프리셋 스트립은 그대로 나온다.
20. `/ask`에 오른쪽 열이 없다. 1440에서 스레드는 760에서 멈추고 가운데 선다.
21. `/ask` 빈 상태: 가운데 정렬 · 컴포저가 화면 가운데, 위에 인사 + 약속 한 줄, 아래에 질문 카드 5장(2열, ≤767 1열).
    익명 줄 없음 · 컴포저 이중 테두리 없음 · 스레드와의 구분선 없음. 칩을 누르면 그 라벨이 전송된다.
22. 익명 줄이 표면 어디에도 없다 (위젯 빈 스레드 · /ask 시작 화면).
23. 회사를 특정하지 않은 첫 질문(「이 공시 조건 알려줘」) → 되묻는 한 줄. 임의 회사로 검색하지 않는다.
24. 새 대화 → 스레드만 비워진다. 저장된 대화 목록이 어디에도 나타나지 않는다.
25. 시작 화면에 새 대화 버튼이 없다. 시작용 카드 4장이 서로 다른 회사를 부른다.
26. 완료 푸터에 `다시 질문`이 없다 (모든 카드).
