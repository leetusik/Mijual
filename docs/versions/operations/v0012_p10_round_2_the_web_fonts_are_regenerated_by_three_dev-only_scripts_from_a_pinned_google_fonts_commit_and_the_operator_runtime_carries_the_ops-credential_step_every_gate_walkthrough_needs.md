# Operations

## Status

Nothing is deployed yet, and the submission truth from P1 is unchanged. What P2 adds is **running
truth**: the pipeline now collects, extracts and gates on a schedule, under explicit budgets, and
every committed artifact can be regenerated at **0 OpenDART requests and 0 LLM calls**. **P3 adds one
local documentation command** (the design grounding-pack export, below) and the
**observation-only operating rules** the ops surface must obey. **P5 built the product on top of
that**: two more offline beat stages, a persisted run log, the operator console itself, and two
processes an operator now runs locally (uvicorn + the Next app). **P6 added the AI 질문 agent**, which
introduces the system's first *in-request* spend, a per-turn ▷ ledger, two conversation tables and
three new deploy obligations. Deployment stays **P4**'s.

**P8 (디자인 폴리시 패스) moved one deploy-critical fact and retired one variable.** The vocky
credential is now **reader-facing**: `POST /feedback` (the 의견 보내기 surface) uses the same
`MIJUAL_VOCKY_API_*` pair as the ops observation read, so an unset or wrong key degrades a **reader**
surface, not only an operator tab. And **vocky sits behind Cloudflare, which bans `Python-urllib/3.x`
by browser signature** — measured 403 `error 1010 browser_signature_banned` without a `User-Agent`
and 200/202 with one. Both calls now send `mijual.web.vocky.USER_AGENT`. This had been **silently
breaking the P5.S18 observation read**: `/ops/feedback` reported 「unreachable」 for an unknown period
and served rows again the moment the header was added. Anything in this repo that ever calls a
Cloudflare-fronted host over `urllib` will hit the same wall.

# Part 1 — Running the pipeline

## Quota and Request Ceilings

- **Daily OpenDART quota: 20,000 requests per key** (operator, corroborated by community
  documentation; ▷ the official page defers to a homepage notice, so this is authoritative-by-operator
  rather than scraped).
- **Every collection run is bounded anyway.** `DartClient(max_requests=…)` raises
  `RequestBudgetExceeded`; a run **stops cleanly and keeps what it collected**. A known cap is not a
  reason to run unbounded.
- **Re-collecting a window is nearly free** — a second live pass over the same window added zero
  events and zero versions for 25 requests. That property is what makes the scheduled job cheap.
- **LLM calls are capped the same way**: `GeminiClient(max_calls=…)` refuses past the ceiling, and a
  budget-exhausted stage is a *reported status*, not a failed run.
- ▷ Total spend to date is roughly **3,100 OpenDART requests** across P1 + P2 (P1 ~1,002; S2 291,
  S3 289, S7 584, S8 ~337, F1 585) — comfortably inside one day's quota. Measured LLM spend, read from
  `extraction_call`: **213 calls, 2,025,260 tokens, ▷ $2.79, 0 failures.**
- **The agent introduces the first spend a reader can trigger, and it is bounded three ways**
  (P6): a per-turn call budget refuses a model call **before** making it, a per-turn round/tool
  ceiling stops a runaway conversation, and a process-wide concurrency cap bounds how many turns can
  be in flight at once. The concurrency cap is the one that actually bounds money, because it is an
  integer nobody can evade. **None of the three is ever rendered as reader-facing copy** — 질문 수
  무제한 is signed, and a limit that is not shown must not be implied.
- **Measured agent cost: ▷ $0.0093 per turn** (`gemini-3.7-flash`, thinking `LOW`, exactly measured
  over 18 model calls / 87,908 tokens across 8 live turns). A full 25-turn verification pass came to
  **▷ ≈ $0.23 estimated, never billed.** Prompt tokens dominate, which is what makes the cheap
  thinking level the right default: the guarantees are structural, so a cheaper level cannot produce
  an unverified claim — only a blocked one.

## Schedule and Budgets

`mijual.scheduler` = Celery beat + worker on the compose Redis (host **6380**, profile `scheduling`),
running **`collect → bodydoc → extract → gates → reparse → snapshot`** in that fixed order.

**P5 added the last two stages, and both are offline** (0 requests, 0 model calls), so scheduling
them costs nothing. They exist because the serving layer reads a persisted precomputation that was
previously hand-run: until they ran on the schedule, the ① extras and the landing headline could
**age silently while 기준시각 said the corpus was fresh**. The order is a data dependency — `reparse`
rewrites `facts`, `snapshot` builds `LapseRow` from them. Measured on the live corpus: `reparse
69/69, 0 with changed facts`, `snapshot ① inputs 545 / 소멸 rows 32`, and `/board/summary` identical
before → after.

**The beat schedule and the run-lock key now have exactly one declaration** (`mijual.beat`,
stdlib-only), read by both the Celery app and the ops panel — so the panel can never render a
schedule the worker is not running.

**Every run writes itself down.** `pipeline_run` is opened before the first stage and closed after
the last, which is why an in-flight or crashed run is visible (a row with no `finished_at`) *and* why
the ops lock chip has an honest 시작 시각 — the Redis lock value is an owner token with no start
time, so deriving one from its TTL would be an invented number. **A skipped run writes no row** (it
did nothing; contention shows on the lock chip). A run-log failure is swallowed into a run note: a
log that can kill a pipeline is worse than no log.

| when (KST, `enable_utc=False`, `Asia/Seoul` explicit) | window | budgets |
|---|---|---|
| daily **07:30** and **19:30** | rolling **14 days** | collect ≤ 500 requests, bodydoc ≤ 200, extract ≤ **60 LLM calls** |
| Sunday **04:30** | **90 days** | collect ≤ 1500, bodydoc ≤ 600, extract ≤ 60 |

- The window is anchored on **KST**, not the host clock.
- **One lock, `mijual:lock:pipeline`, on every corpus-writing entry point.** Re-running a window is
  free, but two concurrent runs double-fetch — and spent quota is the one thing idempotent upserts
  cannot repair.
- **Broker-free fallback:** `python -m mijual.scheduler once [--offline]` runs the same code path;
  `--offline` costs **0 requests / 0 calls** and is the tool the analysis slices reuse.
- **Nothing in the scheduler is reachable from a request path.** The board renders persisted rows
  filtered by `Event.exposure_state`, so a dead worker leaves it **stale, never dark** — which is what
  the 결격 window below requires.

**Open operational decision before a worker runs unattended:** the 정정 해석 task still inherits the
project thinking preset (the three prose tasks run `LOW`). Today's backlog prices at **69 calls**
(정정 R1 59 + R3 10) against `extract_max_calls=60` per run, so the beat drains it in two scheduled
runs — at whatever level the preset happens to be. Decide the level, or cap it, before deploying a
worker (see `decisions` D-4).

## A Corpus Is Not a Census

Two standing practices, both learned by measurement:

1. **Run both sweeps.** A `list.json` census over the *result* filings surfaced three 2026 KOSDAQ ①
   originals an earlier run had missed, and one offering the census itself cannot see (KB스타리츠
   `20260423000439`, filed as 증권발행실적보고서(집합투자증권) outside 발행공시 entirely) which only a
   **per-event backstop** — one corp-scoped, unfiltered `list.json` per closed-청약 event — caught.
2. **Measure the gap before spending on it.** Full-2026 discovery found **244 of 2,279 target filings
   (10.7 %) had never been stored** (`piicDecsn` 192/1,145, `pifricDecsn` 4/25, `cmpMgDecsn` 48/286),
   while **`cvbdIsDecsn` was 0/823** because ②'s backfill window strictly contains 2026 — *a wider
   historical backfill immunises a rights type against the run gap*. The gap check itself is free:
   discover offline, diff the `rcept_no` set against stored versions, then spend.

Repair is cheap and targeted: **per-corp adoption costs 3–4 requests per offering** (22 offerings for
~90 requests, against ~300 for a market-wide historical re-run), lands ordinary corpus rows, and
heals `unpaired_correction` placeholders through the existing `superseded_by_pairing` path.

Two smaller operational rules: **a budget-capped live run must be followed by an offline pass over the
response cache before its numbers are read** (a capped run once left 28 fetched-and-cached documents
unpersisted), and **after re-deriving stored evidence, chase the number into every frozen or rendered
copy** — the gate note embeds it and the frozen evalset sample carries a copy.

Prerequisites: docker (Postgres 16 on host **5434**, Redis 7 on **6380**) and a repo-local `.venv`.

```bash
# infrastructure
docker compose up -d postgres                 # add: --profile scheduling  for redis/worker/beat

# tests + workspace
.venv/bin/python -m pytest                    # 118 tests, ~2.6s, no network/model/DB
python3 scripts/workflow.py validate

# the pipeline, offline (0 requests, 0 calls)
.venv/bin/python -m mijual.scheduler once --offline

# stages and reports
.venv/bin/python -m mijual.collect ...        # live; honours --max-requests
.venv/bin/python -m mijual.bodydoc ...        # live; 본문 ZIP fetch + parse
.venv/bin/python -m mijual.extract labels     # free label tier: 0 calls, 0 requests
.venv/bin/python -m mijual.extract --dry-run recheck   # measure, write nothing
.venv/bin/python -m mijual.gates run          # deterministic, 0 calls / 0 requests
.venv/bin/python -m mijual.gates summary
.venv/bin/python -m mijual.estimate reparse   # re-read stored 실적보고서, 0 requests / 0 calls
.venv/bin/python -m mijual.estimate snapshot  # serving precomputation, 0 requests / 0 calls
.venv/bin/python -m mijual.estimate report --today YYYYMMDD [--korean]
.venv/bin/python -m mijual.evalset report

# the product (P5) — two processes, neither a compose service
.venv/bin/uvicorn mijual.web.app:app --reload --port 8010   # API on :8010
cd frontend && npm run dev                                # or: npm run build && npm run start

# /ops needs credentials on the API process; they are deliberately absent from .env
MIJUAL_OPS_ID=<throwaway> MIJUAL_OPS_PASSWORD=<throwaway> make api-up   # then: make web-up
cd frontend && npm run build && npm run typecheck && npm run smoke   # the frontend's own check

# ...or the whole dev stack at once (the supported path — see the note below)
make stack-up            # postgres + API on 127.0.0.1:8010 + next dev on 0.0.0.0:3010
make stack-status        # pids, the local URL, and this machine's Tailscale URL
make stack-down
```

**Prefer `make stack-up` for the local product, and know what it does for you.** It runs the API
with a **root logging config on purpose** — without one the per-turn agent-spend `▷` ledger line is
recorded nowhere (see *Observability*) — binds `next dev` to `0.0.0.0` so the site is reachable over
Tailscale, and passes this machine's tailnet IPv4 to the frontend as **`MIJUAL_DEV_ORIGINS`**. That
last part is not cosmetic: `next dev` serves its `/_next/*` chunks and its HMR socket **only** to
hosts on `allowedDevOrigins`, and a rejected origin leaves the page rendered but **never hydrated** —
which looks exactly like half a dozen unrelated product bugs and is how P7's eleven complaints
happened. Logs are `var/stack/{api,web}.log`. Starting `next dev` by hand is still fine; set
`MIJUAL_DEV_ORIGINS` yourself if you will browse from anything but `127.0.0.1` or a `*.ts.net` name.

**The dev stack runs on ports nothing else on this machine uses: web 3010, API 8010, Postgres
host 5434.** This was an operator-directed move (2026-08-30), not a preference. `make stack-up`
used to fail at `db-up` because `compose.yaml` bound Postgres to host **5433** and another project
of the operator's holds it — the machine also runs a 창플 stack whose Postgres sits on 5433 and
whose own Postgres sits on 5432:

```
Bind for 0.0.0.0:5433 failed: port is already allocated
make: *** [db-up] Error 1
```

Rather than stopping the other project's container on every run, this project moved: `compose.yaml`
publishes **5434**, `config.py`'s `DEFAULT_DATABASE_URL` follows it, and the Makefile's `API_PORT`
and `WEB_PORT` are **8010** and **3010**. Web and API did not have to move — host 3000 and 8000 were
free, since the other project's web and API listen only inside their containers behind an nginx on
`:80` — they moved anyway, by operator instruction, so the two stacks can never collide.

The same Postgres image and the same `mijual_mijual-pgdata` volume are kept, so **no data moved**.
`allowedDevOrigins` matches **hosts only, never ports**, so the dev-origin allow-list is unaffected
by the change.

**`MIJUAL_OPS_ID` / `MIJUAL_OPS_PASSWORD` are unset in `.env`**, so `/ops` shows only the **door**;
the ops **bar** cannot be seen without them. Set throwaway values on the API process for the duration
of a check rather than writing them into `.env`.

**The re-derivation order after any collection is fixed, and each step invalidates the next:**

```
bodydoc backfill  →  gates run  →  estimate reparse  →  estimate snapshot
```

The trap inside it: `upsert_extraction` clears the gate verdict on **every** write (a re-read
invalidates the previous verdict), so an `extract labels` pass on its own leaves rows with a NULL
`gate_status` and the ③ pages temporarily without the field — **always follow a label pass with
`gates run`**. The scheduled pipeline does this correctly by construction.

**Two freshness caveats worth knowing before an alert is built on 기준시각.** `Event.last_seen_at` is
`onupdate=utcnow` and `gates run` writes every event on every run, while `ensure_event` bumps it
during a collect — so the landing's 기준시각 (`max(last_seen_at)`) is moved to "just now" by **any**
gate run or offline repair, with no OpenDART call involved. **A freshness signal that an offline
maintenance job can reset cannot, by itself, be the alert that the collector stopped.** The ops
panel's 「실행 기록 없음」 row is the honest signal for that.

**Everything that is committed regenerates at zero spend.** The 소멸 estimate, the gate verdicts and
the accuracy report all read the database or two frozen JSON files; two consecutive runs of
`gates run` and of `estimate report` are byte-identical. Re-running extraction is free as well —
already-stored fields are skipped and span re-resolution is a separate 0-call pass.

Cheap deterministic re-derivations, both idempotent: `python -m mijual.extract recheck` (re-scores the
stored 정정 check) and `python -m mijual.evalset refresh-recall` (re-freezes the label-free recall
figure in the frozen sample). Neither re-pays for an extraction.

### Regenerating the web fonts (dev-only, P10.S7)

The shipped faces are **subsets**, so they are regenerated rather than edited. Three scripts, none of
them part of any build or deploy:

```bash
cd frontend
node scripts/gen-korean-charset.mjs        # re-extract every Korean syllable the app renders
                                           #   → scripts/korean-charset.txt (app/, components/, lib/)
bash scripts/subset_noto_sans_kr.sh        # → app/fonts/NotoSansKR.subset.woff2  (291,072 B)
bash scripts/subset_plex_mono.sh           # → app/fonts/IBMPlexMono-{Regular,Medium,SemiBold}…woff2
```

Both shell scripts need `pyftsubset` (fonttools) with brotli, and both pull their source from a
**pinned** google/fonts commit (`4efc2774c63917927efe769ca845def6bd6debae`) so a re-run is
reproducible rather than "whatever upstream is today". Re-run `gen-korean-charset.mjs` **whenever
Korean copy is added or changed** and then re-subset — the charset is auto-extracted precisely
because a hand-kept one goes stale and renders missing syllables 자모 분리. Coverage is
`HANGUL_COVERAGE` in `subset_noto_sans_kr.sh`: the default adds the **KS X 1001** wansung set on top
of the extracted glyphs (so dynamic DART company names render in the shipped face), and `full` adds
the whole 11,172-syllable block for +732 KB. Both OFL licence files ship beside the fonts.

### The design grounding pack (P3)

```bash
.venv/bin/python scripts/export_design_grounding.py            # → docs/reference/design/grounding/
.venv/bin/python scripts/export_design_grounding.py --out DIR  # export elsewhere (safe for a diff check)
```

- **A documentation tool, not product code.** It writes only under its output directory, and nothing
  under `src/mijual/` depends on it. It regenerates the anti-lorem pack the design rounds were
  designed against: `board-snapshot.md`, `headline-numbers.md`, `copy-inventory.md` and 11 pinned
  `EventExposure` / `FieldView` sample JSONs (the three prose pages in the pack are hand-written and
  are not touched).
- **0 OpenDART requests, 0 LLM calls** — everything is read from the local Postgres corpus through the
  same modules the product will use (`mijual.gates.exposure`, `mijual.cb`, `mijual.estimate`,
  `mijual.calc`). Verified by re-running it, and the two CLIs it shells out to, with every
  non-loopback socket blocked.
- **Deterministic on a fixed corpus and anchor:** two runs in the same session are byte-identical.
  It is **anchored on today**, so a run on a later date legitimately changes `measured_at` and every
  D-day label — that is drift in the anchor, not in the data. Every artifact carries its measurement
  date and the command that regenerates it, so a stale figure is always distinguishable from a changed
  one. **Diff a re-run into `--out <scratch>` rather than over the landed pack** unless you intend to
  re-date the record the signed design rounds cite.
- **It exits non-zero if a pinned sample has left the corpus** (reported as a `GAP` rather than
  silently substituted). Samples are pinned by `rcept_no` **and** exposure state, because one
  `rcept_no` can belong to several events.

## Deployment — the two 결격-grade constraints

1. **Uptime window.** "제출된 웹서비스 URL은 2026. 9. 7(월) 11:00 ~ 9. 11.(금) 23:59 동안 접근
   가능하여야 하며, **접근 불가 시 결격 사유에 해당합니다**" — five consecutive business days of
   unattended reachability. A single outage disqualifies the entry.
2. **URL freeze.** "배포 URL은 최종 제출 이후 변경된다면 불이익이 발생할 수 있습니다.
   (**제출한 URL만 인정됩니다**)" — the URL entered at 9/7 10:00 is final.

Consequences that are requirements, not polish: uptime monitoring and a rollback/standby path are
mandatory; **the board must render from persisted snapshots with no OpenDART call in the request
path** (P2 satisfies this structurally — see `architecture`); the URL must be decided before the
freeze; plan for a platform hostname by default.

**The AI 질문 agent does not weaken either constraint, but it adds three deploy obligations** (P6):

1. **Create the conversation tables before the first question.** There are no migrations, and
   `create_all` otherwise runs only from the collect/gates/pipeline entry points — so a fresh deploy
   database has no `conversation_turn` / `conversation_feedback` and every turn fails at persistence.
   Creating them is additive and idempotent (measured: 16 → 18 tables, nothing existing touched).
2. **Preserve the streaming response's headers end to end.** `Cache-Control: no-store,
   **no-transform**` and `X-Accel-Buffering: no` must survive every hop. A proxy that re-encodes the
   stream (Next's own router does by default, and so will a CDN) buffers it, and the reader gets the
   entire answer in one burst after a long blank wait — the signed streaming state simply does not
   happen. This was found in a real browser and not by `curl`, which sends no `Accept-Encoding`.
   **Also budget for idle timeouts:** there is no heartbeat, and the longest observed gap between
   frames with the live agent is **6.0 s**, so an idle timeout below ~10 s will cut legitimate turns.
3. **Install a root logging configuration**, or the ▷ agent-spend ledger is written nowhere (see
   *Observability*).

**A dead board is still worse than a stale one, and the agent inherits that ordering**: it reads
persisted rows through the same loaders, so a dead worker leaves it answering about a stale corpus
rather than failing. What it cannot survive is the model being unreachable — which degrades to the
signed 중단 row, keeping any partial answer, and never to an invented one.

## Observability

- Minimum bar set by the 결격 window: an external uptime check on the submitted URL covering
  2026-09-07 11:00 → 09-11 23:59, with an alert path that reaches the operator.
- Pipeline side: every stage prints its counts, its request/call spend and a ▷ cost line; the beat's
  budgets make a shortfall visible as a reported status rather than a silent stall.
- **Agent side (P6): one ▷ ledger line per turn, in the server log and nowhere else** — rounds, tool
  calls, blocked sentences, model calls, tokens, thinking level and the ▷ estimate, rendered by the
  ledger's own renderer so there is exactly one renderer and one rate card. A disconnected turn logs
  its own line. **It deliberately does not appear on any signed ops panel**: R7 signs the 정확도·비용
  tab's LLM spend as *extraction-call aggregation* specifically and its quota bar as the extraction
  budget, so adding an agent row there would be a design change this phase may not make. The numbers
  are recorded; the panel is left alone.
- **⚠ That line is invisible under a default `uvicorn`, and P4 must fix it.** It is `log.info` on the
  ask module's logger, and uvicorn configures only its own loggers, so the root logger stays at
  `WARNING` and **agent spend is recorded nowhere at all** (verified both ways: zero lines plain, the
  line appears the moment a root logging configuration is installed). Nothing was added to the
  application, because a library that calls `basicConfig` pre-empts the deployment's own choice —
  **so the deployment must make one.**

### The operator surface — signed at P3 R7, **built in P5**

The 운영 관제 panel exists at `/ops`: a door plus six tabs (개요 · 게이트 대기열 · 정확도·비용 ·
대화 로그 · 사용자 · 피드백), desktop-only, read-only, over thirteen `/ops` routes. These are
operating rules, not UI notes, and each one below is now implemented and measured:

- **Pure observation — no mutation endpoints anywhere.** No review/clear/approve/re-run control, no
  status bits on the queues. **Exposure changes only through the pipeline CLI**, so no click can
  silently override a deterministic gate verdict.
- **A beat that did not run renders as an alert-ink 「실행 기록 없음」 row**, derived from the scheduled
  time. Silence must never read as success. A **budget exhaustion is a reported status, not a
  failure style** — alert styling is reserved for did-not-run.
- **Sources, not restatements:** the beat schedule renders from the Celery beat configuration (never
  hardcoded); the accuracy view prints what `mijual.evalset report` emits, with the **`judged_by`
  provenance block above the numbers** — 98.6 % never appears without it; ▷ cost markers are printed
  verbatim from pipeline output; open pre-launch items (D-4's thinking-level question) are read from
  `decisions` rather than restated in the panel.
- **The pipeline lock** `mijual:lock:pipeline` is surfaced live as a chip (held/free + holder + ttl +
  held-since, or an honest `unknown`). It polls its **own cheap endpoint** every 15 s from all six
  tabs, because the 개요 read walks 488 events and polling that would have made the chip the most
  expensive thing on the surface. **Redis being down is a fact the operator wants, not a reason to
  fail the page**: a dead broker returns 200 in ~0.13 s with `state: "unknown"` + the reason and the
  rest of the tab intact.
- **The cumulative quota bar is labeled as cumulative, not daily**, and the OpenDART quota's
  denominator is served **with its provenance** (`operator (decisions O-1)`), because 20,000/day is an
  operator statement, not something this service can measure.
- **Reason codes and suppression codes render verbatim in English**, unknown codes included — no
  Korean was invented for them and no fallback copy is allowed. `foreign_correction_head` (new in P5)
  joins the list.
- Gate-queue rates are computed on **distinct `(rcept_no, field_key)` = 691**, not the 710 stored rows
  (19 duplicates) — it moved from 633/649 when the label field landed. **Both numbers are served**
  (`basis.stored_rows` / `distinct_rows` / `duplicates` / `key`) and every reason carries its stored
  count *and* its distinct count + rate, so no percentage's denominator is ever implicit.
- **가동 전 미결 is a quotation surface**: the 개요 tab reads `docs/current/decisions.md` and quotes
  its still-open bullets **verbatim** with the document's own version, or states that the file is
  absent. Nothing there is re-worded, summarised or authored.
- **`▷` is stored and served verbatim inside this panel** and never becomes 「추정」 — the boundary is
  the source. Everywhere else in the product 「추정」 is the only estimate mark.
- ~~**The three P6-facing tabs serve honest zeros.**~~ — **alive since P6, with no route and no
  component change.** 대화 로그 / 익명 세션 / the feedback queue read the same storage-agnostic port;
  P6 filled it with the real implementation and the tabs simply started returning rows. Verified on
  live data: the log shows real turns (세션 · 시각 · 범위 · 질문 · 답변/거절 · 거절 카테고리), an
  expanded row replays the answer with its 근거 and its **verbatim** 인용, both filters work with the
  **five signed Korean family names as their values**, 익명 세션 aggregates sessions with their
  question and refusal counts and last 범위, and the queue holds the saved 의견 with its optional
  reply address and a link back to the conversation. **Still pure observation** — no delete, edit,
  tag or status control anywhere, and the conversation schema carries no status bit to add one to.
- **The conversation log is the agent's quality instrument, and it records the broken turns too.**
  An aborted, errored or mid-stream-cancelled turn is stored the same way as a completed one, so the
  log shows what readers actually saw rather than only what succeeded. Nothing about the mechanism is
  stored; `aborted` versus `error` lives in the server log beside the ▷ line.
- **The vocky observation view is the 피드백 tab**, reading vocky's own feedback API server-side with
  the key never reaching the browser. It degrades in three states (`ok` · `unconfigured` ·
  `unreachable`), **never 500s and never fabricates a row**, and is bounded: 3 s timeout, no retries
  (measured — dead port 12 ms, wrong key 33 ms, blackholed host 3.03 s).
- **The 개요 tiles and the 정확도 markdown are byte-for-byte reproductions** of
  `python -m mijual.gates summary` and `python -m mijual.evalset report`. Verified live.

## Knowledge (phase explainers)

The `explain` skill ships with this workspace, in `.claude/skills/`. Explaining is an **operator-run
step, separate from the phase review**: run `/explain` for a phase when you want one and it saves an
interactive HTML explainer to the knowledge service. The review itself writes no explainer — it only
reports the pointer `explain: not written — run /explain for this phase`.

**Setup is on first use, and it asks first.** Run `/explain`; if no knowledge base is configured it
offers to create one on the hosted service at `https://knowledge.hi2vi.com` — it asks for an email,
installs the `knowledge` CLI, signs you up (or logs you in), and writes an org-level key to
`~/.config/knowledge-kb/config.json` at mode 0600. One org key serves every repo.

Already have a knowledge base — hosted or self-hosted? Skip the setup by exporting the credentials in
`~/.zshenv` (never a repo `.env`):

    export KB_API_BASE_URL="https://knowledge.hi2vi.com"
    export KB_API_TOKEN="vk_..."

  `/plugin install knowledge@knowledge` → `/knowledge:setup`, then `/knowledge:explain`.

- **Cross-process rate-limit state.** The agent's two ceilings are per process, so N workers means N
  times the concurrency cap. It bounds spend adequately for one process and is documented as
  evadable by a client that mints a fresh session handle; a shared counter is P4's, alongside login

- **Nothing prunes conversation rows either.** They are anonymous and small, but they grow
  monotonically like the session tables, and unlike every pipeline table they are **not
  re-collectable** — so a retention decision is the operator's, and a reaper must be written knowing
  that a deleted turn is gone for good.
- **The dev database now holds real conversation rows** from the verification pass. They are the
  product's own anonymous log and are what make the three ops tabs demonstrably alive; an ordinary
  delete clears them if a clean log is wanted.
- **Expired `auth_session` / `ops_session` rows are never pruned.** They grant nothing once expired,

- **Two stated defaults are still the operator's to confirm**: the countdown cut-off instant (end of
